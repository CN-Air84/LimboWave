## 教学不是放手探索

七个短练习共用一张持续变化的配置图：
1. 连接地址、协议、密钥归站点端点管理。
2. 同名模型位于不同站点，是不同实际模型条目。
3. 分别填写逻辑 ID xyz-chat、显示名称 XYZ Chat，保留实际型号，再验证“未绑定不能调用”。
4. 先后绑定 甲站/乙站的实际模型，不把端点裸地址当绑定。
5. 调整首选顺序，先预测，再用项目真实 RoutingService 验证去向。
6. 查实际模型的工具/流式/思考能力，不凭相同模型名字猜。
7. 模拟首选失败，明确选另一站点，再主动验证重试；默认顺序不变。

只点“继续”无法过关。选错给出具体解释；“带我看一步”提示要看哪里、做什么，不自动替用户作答。支持键盘、返回重练、深浅色、暂离，无扣分、倒计时、生命值或强制登录。

## 不碰真实配置

全部数据在内存中；站点使用 `.invalid`，没有密钥输入，不联网、不调用模型、不读取资料库、不保存进度。真实 schema 和 RoutingService 仅进行纯本地校验。练习的能力差异是教学数据，不是提供方能力承诺。

完成页告诉用户各操作的具体设置入口、首次引导自动完成过的默认绑定，以及“绑定不保证效果一致、失败不静默跨站”的边界。不把本次练习冒充已经改好用户真实配置。
