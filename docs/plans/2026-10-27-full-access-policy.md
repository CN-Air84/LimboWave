# 完全访问统一放行实现计划

**Goal:** 本地会话选择“完全访问”时，应用层权限统一自动允许，不再只跳过 UI 弹窗却被底层权限/网络策略拒绝。

**Architecture:** 从已持久化的会话档位推导调用级权限上下文，不能由模型参数伪造；用 ContextVar 隔离并在退出/异常时恢复。默认档位与远程 Web 来源维持原有边界。参数合法性、运行/分支有效性、数据版本一致性、TLS 校验、超时和输出限额不是审批规则，不取消。

**Tech Stack:** Python / pytest / PySide6 / Pi TypeScript extension。

## 设计选择
- 仅改提示词不能解决 HTTP 传输层拦截，不采用。
- 全局删除安全检查会连带影响非完全访问与 Web 端，不采用。
- 采用会话派生的统一规则；仅在受信任本地完全访问调用内放行。

## 步骤与原子提交
1. 权限服务加入完全访问最高优先级 allow 规则，保留明确用户拒绝和审计；新增会话隔离回归。
2. 将完全访问传递到工具执行及每跳 HTTP：内网、Fake-IP、非标准端口、跨域跳转无需再确认；保留普通模式原校验，覆盖异常恢复及跨会话隔离。
3. 对齐文件范围、记忆审批及能力说明中与完全访问冲突的分支；保留来源鉴别、上下文有效性、数据完整性，补充回归。
4. 同步用户可见说明，运行权限/网络/记忆/来源边界相关测试与静态检查，检查差异并逐项提交。

## 验收
- 本地完全访问，无临时 user_confirmed 标记也能通过统一权限规则。
- 默认/自定义调用仍拦截非公网与未授权操作；Web 调用不能借用完全访问。
- 权限上下文退出后不污染共享传输对象、后续调用或并发任务。
- 所有审批规则可在审计中追溯，错误参数与失效运行仍正常报错。
- 不测试真实云元数据、凭据或破坏性命令：只使用本地夹具和 mock。
