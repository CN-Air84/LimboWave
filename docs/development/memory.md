# 记忆功能

## 使用

- **设置 → 记忆**：管理全局记忆，分别设置全局/会话记忆提醒间隔（1–30轮，默认15），选择模型写入会话记忆的默认策略。
- **会话工具栏 → 记忆**：管理当前分支记忆，选择该会话的“继承全局 / 每次询问 / 自动允许”，或将选中的会话记忆升格为全局。
- 两个管理界面都支持新增、编辑、删除。保存正文与保存设置为独立操作。
- **会话工具栏 → 记忆 → 记忆编辑 → 全局记忆 · 仅本会话定制**：为当前会话修改或删除继承的全局条目；卡片显示“继承全局 / 本会话已修改 / 本会话已删除”。这里不能新增或升格全局记忆。
- 升格创建独立全局副本，影响所有会话；保留原会话记忆，后续编辑、删除不互相同步。
- 默认每次询问。审批显示完整可滚动纯文本；关闭、拒绝、取消运行均不写入。本地“完全访问”预先授权记忆操作，免去弹窗；其他档位保留审批。

新会话无需先发送消息：点击“记忆”会按需保存一个空会话及分支，并直接打开管理面板；不会调用模型，也不会添加虚假消息。输入框草稿保留，首次发送会沿用该会话并应用已定制的记忆。

## 内置预设：忠实的阅读者

应用自带一条「忠实的阅读者 · 内置预设」，作为普通全局记忆生效，不是不可修改的系统提示词。它强调坦然的机器身份、不虚构人类生活与情绪，以阅读和回应而非诊断与修理为先，并据实说明工具意图、记忆来源、查询结果及上下文整理。透明必须以实际发生的行为为依据，不得虚构查阅、无限记忆或无遗漏的承诺。

- **设置 → 记忆 → 记忆编辑**：双击预设卡片或按 Enter 可修改全文（包括首行标题），也可删除；修改在下一轮对话生效。
- **会话工具栏 → 记忆 → 记忆编辑 → 全局记忆 · 仅本会话定制**：可以只调整当前会话的预设，或只在该会话停用、恢复它，不影响其他会话。
- 首次运行包含此功能的版本时，在资料库服务装配阶段、后台线程中初始化，新旧资料库都适用。已有全局及会话记忆保持不变；不会在每次读取记忆时插入预设。
- 正文与独立的 `preset-installed:builtin:faithful-reader` 初始化回执在同一事务中加密保存到 `memory_documents`，无需新增数据库迁移。重启和后续初始化不会覆盖用户修改，也不会复活已删除的预设；整库备份/恢复会同时保留正文与回执。重置并新建资料库则重新提供默认预设。
- 全局空间不足（100条或32000字）时不强塞预设、不删改已有记忆，也不阻止启动；留出空间后，下次启动再尝试初始化。用户已经安装后主动删除的情况不会重试。
- 预设沿用现有记忆周期、会话覆盖及运行快照规则；不增加模型权限，不改写 OOBE，也不另行注入隐藏的默认正文。

## 会话级全局记忆定制

全局原文仍在“设置 → 记忆”中统一管理。会话内编辑保存的是独立覆盖；“仅本会话删除”只是不再向该会话的模型提供这一条，不删除全局原文，也不影响其他会话。已删除的条目仍在管理列表中显示，选择后可“恢复全局版本”。恢复会移除本会话的定制，重新继承**当前**全局正文，而非定制时的旧版。

- 未定制的条目继续继承全局更新和新增；已修改的条目使用本会话正文，已删除的条目保持不注入。
- 如果在全局设置中真正删除原条目，它也会从各会话的有效列表中消失；同文字的新条目拥有新身份，不继承旧覆盖。
- 定制属于会话而非分支：同一会话的所有分支共用，包括从历史消息创建的新分支。分支记忆的历史快照机制不变，不会回滚会话级定制。
- 修改、删除或恢复在下一轮对话生效，已经开始的运行保留其记忆快照。切换会话时按目标会话重新解析，不串用当前会话的覆盖。
- 编辑仍限制为1–4000字，保存时检查当前有效全局列表最多100条、32000字；超限拒绝整个编辑。全局原文后续更新不自动改写已有定制；删除和恢复继承始终可用。
- 关闭编辑窗口、切换编辑范围或取消删除不会保存草稿；条目已被全局删除时，保存明确报错，不创建新条目。

## 轮数与提醒

一轮对应分支有效历史上的一条已持久化用户消息。工具往返和运行内部重试不增加轮数；发送前被拒且未落库的输入不计数，已落库的失败轮仍计数。

首轮注入记忆，之后每隔指定轮数重新提醒。例如间隔15时，第1、16、31轮更新提醒位置。两类记忆独立计时，内容在各自最近的提醒位置保留，不在每轮重复堆积副本。新增、编辑、删除记忆会在下一轮刷新；同一运行使用固定快照。

恢复运行时、切换分支以及压缩后重建有效记忆提醒。记忆通过 Pi 统一 `context` hook 提供，不修改用户消息，不手工拼接提供商请求协议。记忆作为应用提供的参考信息，不作为系统权限指令。

## 分支与历史

模型写入审批策略属于会话；普通会话记忆内容属于分支，全局记忆定制由整个会话共用。每轮开始将当前分支记忆列表加密保存为不可变历史快照。从旧用户消息编辑或重新生成时，新分支继承该原轮开始前的快照，随后各分支独立维护。

因此，父分支后续生成、修改或删除的记忆不会倒灌到历史分叉。当前记忆的删除不物理清除旧分支快照；从历史位置分叉仍可能恢复当时存在的记忆。删除整个会话会级联清除它的当前记忆、快照、策略、全局记忆定制及模型写入回执，但不删除已升格的全局副本。功能上线前的历史消息没有快照，分叉保守继承空会话记忆。

## 数据与工具边界

- `memory_documents` 保存全局列表、分支列表、每轮快照、会话策略、全局记忆定制和幂等回执。正文与快照均通过资料库 `VaultKey` 加密；SQLite 与内存仓库实现相同事务契约。
- 基础记忆表由版本9迁移创建；会话级全局定制复用该表，以 `global-overrides:<conversation_id>` 文档加密保存覆盖正文和删除标记，关联会话但不关联分支，无需新增数据库迁移。现有整库备份/恢复及数据重置自动覆盖这些记忆文档。周期和全局默认策略保存在普通配置中，不含正文。
- 单条最多4000字；每个记忆范围最多100条、32000字。超限明确拒绝，不静默截断。
- 模型工具 `add_session_memory(content)` 只能添加当前运行所属分支的记忆。调用标识和运行标识由扩展追加，服务端再与活动运行核对。
- 批准绑定运行、分支、调用标识及确切正文；IPC 的 `confirmed=true` 本身不能授权。调用重复派发不重复添加，即使用户后来删掉该条也不会复活。
- 模型可通过 `update_memory` 提议更新当前会话可见的全局记忆原文，非完全访问时每次需明确确认全局影响范围；全局新增、删除、升格和会话级全局定制仍由用户手工管理。

## 主动记忆检索与透明便签

### 模型工具

| 工具 | 用途与边界 |
| --- | --- |
| `search_memory(query, scope="all", limit=10)` | 主动检索已保存记忆，不用等待周期提醒。范围见下表；每次最多20条。 |
| `update_memory(memory_id, updated_content)` | 提议整体更新当前分支记忆或本会话可见的全局原文；保留 ID、初次记录时间和来源，更新修改时间。两种范围在非完全访问时每次都需用户确认。 |
| `delete_session_memory(memory_id, archive=true)` | 默认归档当前分支的有效记忆；只有用户明确要求删除才设 `archive=false`。非完全访问时每次都需用户确认。 |
| `read_scratchpad()` | 读取当前分支透明便签的 `content` 和 `revision`。 |
| `write_scratchpad(content, expected_revision)` | 整体替换短期便签；空正文清空。版本必须与最新读取一致，冲突时不覆盖现有内容。 |

`search_memory` 的范围：
- `all`：当前分支有效记忆 + 本会话有效全局记忆，**不含归档或其他会话/分支**。
- `session`：仅当前分支有效记忆。
- `global`：仅本会话有效全局记忆，遵守会话级修改和删除覆盖，不泄露被覆盖的全局原文。
- `archived`：仅当前分支归档记忆。

检索是本地、忽略大小写的**字面关键词匹配**，不是向量/语义检索。多个空格分隔词必须全部匹配，标题命中优先。查询词为1–500字，返回 `id`、`scope`、正文摘录、创建时间及 `content_truncated`；可将返回的 `id` 作为 `query` 精确读取该条完整正文。`has_more` 或 `output_truncated` 表示应缩小关键词/范围；不会伪装成完整结果。跨会话聊天正文仍走原有 `query_chat_history` 及独立审批。

更新/归档/删除的确认框显示完整原文及新正文或操作效果。仅“自动允许添加记忆”不会免除变更确认；本地“完全访问”自动允许新增、更新、归档与删除，不再逐次询问。一次性授权绑定运行、调用、分支、记忆原版和规范化后的操作参数；确认后原文变动、运行取消、参数被替换都会拒绝执行。相同已执行调用通过加密回执幂等返回，不重复应用或复活已移除的记忆。

**全局更新也可以弹窗授权。** `update_memory` 根据记忆 ID 解析目标范围；全局目标的确认框标题为“更新全局记忆？”，显示实际全局原文、新正文及“会影响所有继承这条记忆的会话”。批准后更新全局原文，不创建分支副本，不覆盖任何会话已有的自定义覆盖或停用设置；各继承会话于下一轮刷新。当前会话如有覆盖，仍继续使用覆盖内容。拒绝、关闭或取消运行不写入。

授权额外绑定目标 `scope` 与全局原版，范围不能在确认后替换。审批后原文变化、条目在当前会话被停用或容量不足都会拒绝写入，已有内容保留。全局更新的权限审计标记为高影响操作，并保存作用域；已存在的旧会话写入回执兼容默认 `scope="session"`。

`delete_session_memory` 仍只归档/删除当前分支记忆，不用于删除全局记忆。模型不直接修改会话全局覆盖或归档内容；这些操作继续由用户在记忆面板管理。

**哪些操作会进入确认弹窗？** `search_memory` 返回 `allowed_operations`：会话条目支持 `update_memory` 和 `delete_session_memory`，全局条目支持 `update_memory`，归档条目不支持模型写操作。`model_writable=true` 仅表示可以提出变更，不代表已授权。扩展先通过受运行身份限制的只读检索核对精确 ID；全局更新会继续进入确认，已移除/不可见的条目或对全局条目调用会话删除工具则返回具体错误，并明确说明“未提交审批，也未执行”，不会冒充用户拒绝。

预检不创建写授权，不能替代一次性授权和执行时原文版本核对。“完全访问”免去会话或全局更新弹窗，其他档位仍询问；自动允许添加记忆不能免除更新确认。意外审批错误仅记录阶段、异常类型及运行标识，不写记忆正文。回归测试覆盖非完全访问下真实 FloatingPanel 的会话/全局允许及拒绝流程，以及 FULL_ACCESS 无弹窗自动允许和不伪造 user_confirmed 的审计，并经真实 Pi 验证全局更新能够进入审批、执行后确实更新全局原文且保留会话覆盖。

### 透明便签与归档界面

在**会话工具栏 → 记忆**中新增：
- **透明便签**：查看、编辑、保存、读取最新版本或确认后清空。最多4000字，不进入正式记忆，也不参与升格。保存冲突会保留编辑草稿并提示重新读取，不静默覆盖。没有自动过期删除；由 AI 或用户及时整理。
- **归档记忆**：查看完整归档正文、恢复为当前分支记忆或确认后删除归档。归档不再参与日常记忆注入；显式 `scope="archived"` 才可查到。归档空间单独限制为100条、32000字；满时拒绝整个归档操作，不丢失原条目。

“私有”指按分支隔离，而不是向用户隐藏。便签只应记录简短事实、近期计划和明确标注的待确认事项，不用于隐藏思维链、密钥或未经证实的敏感推断，也不能绕过用户拒绝保存信息的意愿。

便签在每轮开始随记忆上下文读取，经 Pi `context` hook 临时提供，不改写用户消息，不累积重复注入。模型明确读写便签成功后，同一运行后续请求也使用工具返回的新版本；用户在界面中的修改于下一轮生效。新版本替换旧注入，清空移除注入，切换分支和压缩重建后保持隔离。正式记忆仍保留原有独立周期提醒。

### 存储与安全

沿用加密 `memory_documents`，无额外数据库迁移：
- `scratchpad:<branch_id>`、`archive:<branch_id>` 保存便签与归档；
- `scratchpad-snapshot:<message_id>`、`archive-snapshot:<message_id>` 与每轮记忆快照一同保存，历史分叉不会继承未来的便签/归档；旧消息没有快照则保守继承空内容；
- 变更回执和权限审计都由现有加密资料库保存，删除会话时级联清理；整库备份、恢复与重置沿用原有机制。

所有工具的运行/调用 ID 由扩展追加、服务端核对，不接受模型指定其他会话或分支。Web 来源继续执行现有工具拒绝边界；扩展的 `tool_call` 诊断日志不记录检索词、记忆正文或便签正文。工具结果和便签会按正常模型请求发送给用户配置的模型服务，不能把“加密落盘”理解成不向模型提供内容。删除/清空只移除当前有效条目或注入，不物理擦除历史快照、已保存工具结果或已发送给模型的内容。

### 验证

新增测试覆盖双存储后端的范围隔离、全局覆盖、中文/Unicode 检索、完整正文与输出上限、审批/参数篡改/取消/陈旧原文、回执幂等与分支绑定、便签并发版本检查、历史分叉、加密和级联删除。UI 测试覆盖便签冲突保留草稿、清空确认和归档恢复；真实 Pi 测试覆盖新工具执行、审批、诊断脱敏及便签上下文替换/清空/分支隔离。

## 足迹 · 记忆时间线画廊

- **侧栏 → 足迹**：独立的全窗口画廊，不需要新建会话或发送消息。返回时保留对话与输入草稿；“管理记忆”进入现有设置页的记忆管理。
- 按设备本地日期分组，支持最近/最早排序、正文及来源对话搜索、全局/会话范围、来源和月份筛选。每次呈现40条，更多内容按需展开；长记忆可展开完整纯文本，支持选择复制。
- 顶部导航和筛选使用不透明背景板，记忆列表外围保持透明，仅每条记忆保留卡片底色。向下滚动会收起大标题、记忆统计和“仅本地浏览”提示，并将剩余顶部面板上移一半：上半截滑出窗口，下半截贴在窗口顶边。回到顶部后完整恢复；Ctrl+F 或键盘聚焦上方控件时也会展开面板，Esc 始终可返回对话。
- 显示最初保存时间；模型写入的记忆在来源运行和消息仍可用时，同时显示关联对话的写入时间，并支持回到对应消息/分支。无来源消息时只返回所在对话；来源已删除时不伪造日期或链接。
- 后续人工编辑和 `update_memory` 保留条目的原始 `created_at` 与来源，使用可选 `updated_at` 表示最近整理时间。这两个字段仍在加密正文内；旧JSON没有新字段时兼容读取。功能上线前已经被覆盖的创建时间不可恢复，画廊不编造历史。
- 只读取当前全局和分支记忆列表。未改动的同一分支记忆副本合并展示，分支间不同正文分别展示；升格后的全局副本拥有独立身份。已删除/归档条目、轮次快照、草稿、审批回执和会话级全局覆盖不会被重新展示。删除会话后，其会话足迹随之消失，已升格的全局副本仍保留。
- 画廊读取在后台线程的单次只读事务中完成，不新增数据库表、不写明文缓存、不触发模型请求。打开、点击刷新或页面可见时模型运行结束会重新读取；关闭后忽略迟到结果并释放页面数据。

### 加密标识的真实边界

“本机加密保存”指现有 `VaultKey` 对记忆正文的本地加密存储，而不是整库元数据加密，也不是内容永不离开设备的承诺。只有资料库可用时才开放此入口。画廊浏览和筛选本身不上传内容；对话记忆注入可能将相关内容发送给用户选择的模型，主动导出/备份和远程访问也可能使数据离开设备。这一边界在页面顶部展开时提示，顶部面板滑回后可通过锁标识展开详细说明。

## 完全访问与数据一致性

`full_access` 是本地会话的统一预授权，不是模型传入的 `user_confirmed`。
即使没有先走 UI gate，工具网关也按真实档位允许记忆写入；仍检查运行/分支身份、
当前可见的记忆范围、原文版本与幂等回执，拒绝失效运行、跨分支篡改和重复调用变参。
调用内不执行话题禁区拦截，但不删除已保存的规则，不改变普通上下文自动复用策略。
Web 来源、没有实现的全局删除/新增工具及未配置服务不会因此获得新能力。
