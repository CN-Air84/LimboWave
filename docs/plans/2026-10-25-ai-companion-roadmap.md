# LimboWave 可信 AI 陪伴统一开发规划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> 执行环境无此前缀技能时，使用已安装的 `executing-plans` 工作流。此处是实施方法说明，不是立即执行所有里程碑的授权。

**Goal:** 以日常对话陪伴为主要定位，在不削弱权限、加密存储与分支语义的前提下，形成行为诚实、理解可修正、现实信息可核验、约定可兑现、数据可控制的 AI 朋友体验；不通过模拟人类生活或诱导依赖实现陪伴。

**Architecture:** 沿用现有 domain → application → infrastructure/UI 分层，以版本化行为规范、每轮有效能力快照和上下文清单连接模型与应用。模型通过唯一工具网关提出查询或操作；应用服务负责授权、持久化、调度、来源追踪与可见回执。记忆、历史、提醒分别只有一套权威服务；桌面不同视图共享现有运行状态，不新增独立 Agent 内核。

**Tech Stack:** 当前仓库的 Python、PySide6/qasync、Pydantic、SQLite 应用层加密仓库、Pi TypeScript 扩展、现有 Web/React 前端、pytest/pytest-qt 与 Web 测试工具链。此规划不选定新的外部服务或依赖版本。

**状态：** 合并版正式开发规划；包含需求契约、工程依赖和阶段验收，具体实施按里程碑另行授权。日期：2026-10-25。
**来源：** 合并用户提供的 Gemini 开发建议及另一轮基于当前仓库的陪伴能力缺口评估；本文是两者的唯一主路线图，不再另建平行的可信陪伴规划。
**本次范围：** 整理并合并规划，不实现功能、不进行完整安全审计。既有测试证据与未来验收要求严格区分，见第 11 节。

## 1. 如何解释本文

- **原始目标**：来自用户明确的陪伴定位、OOBE 表达、Gemini 建议与本地仓库评估。
- **现状核对**：仅指本次工作区中读到的实现，不代表已发布版本或已完成验证。
- **拟议契约**：为消除歧义而补充的接口、状态与验收条件；不是现有能力。
- **建议默认值**：本规划提出的最小实现选择，可在对应里程碑开始前调整。
- MUST = 对应功能交付必须满足；SHOULD = 默认遵循，偏离需要说明；MAY = 可选扩展。

产品目标可简化为：**通过可追溯、可撤销、可预测的系统行为提供陪伴体验，而不是通过模拟人类经历或制造情感依赖实现。**

不将“陪伴感”“温度”“安心”直接作为可测试需求。它们分别落实为低打断、状态可见、数据可控、行为诚实等条件，再通过用户体验评估验证。

### 1.1 合并与去重规则

- 保留 Gemini 功能包的 TIME-01、MEM-01/02、NOTE-01、CTX-01、UI-01/02、HIST-01、PRES-01 和 BEH-01 编号。
- 新增工程缺口使用 CAP-01、NET-01、HIST-02、CMP-01、PRIV-01/02、WEB-01、VOICE-01、BEH-02、EVAL-01；它们是同一规划的补充，不是另一个产品或运行内核。
- “记忆变更提案”复用 MEM-02 的更新/归档审批与执行路径，不再增加并行的 update/delete API；“小约定”首版复用 TIME-01，不新建另一套调度器。
- HIST-01 是用户时间线；HIST-02 是模型历史回读。两者共用权威消息 ID 与来源信息，不复制聊天库。
- 两份建议原先的优先级仅用于溯源；合并后的实际顺序以第 7 节为准。所有标注“拟议”“建议”的配置与接口均不是当前已实现能力。

## 3. 全局约束与非目标

### 3.1 安全、权限与透明性

1. 所有模型发起的读写 MUST 经过现有工具网关；不得新增旁路文件、任意脚本或独立秘密数据库。
2. 运行身份、调用 ID、会话与分支归属 MUST 由可信运行上下文绑定；模型提交的 ID 只是资源选择，不是权限证明。
3. 审批 MUST 绑定操作、目标、内容/版本和有效运行。等待审批后重新验证；切换会话、运行取消、权限撤回后旧批准失效。
4. 数据变更 MUST 有持久化成功回执；未成功不得向用户宣称“已记住”“已设置”“已删除”。重试不得产生重复副作用。
5. 检索结果、天气结果和旧便签 MUST 被当作资料，不得成为覆盖当前系统权限或用户明确要求的指令。
6. MUST 区分存储加密、传给模型的内容、通知预览、日志和导出：本地加密不意味着已选远程模型不会收到被注入/检索的内容。
7. 新增正文、搜索查询和变更前后内容 MUST 避免进入明文诊断日志；新审计记录应遵循同等敏感数据保护要求。
8. 透明性指操作目的、范围、来源、结果和失败状态可查看，不要求暴露模型内部思维链，也不要求逐条弹窗打断。

### 3.2 体验边界

- 用户 MUST 能停止当前生成、拒绝待审批操作、关闭主动触达、退出迷你形态。
- 纯净模式 MAY 折叠执行详情，但 MUST 保留权限请求、关键变更、错误、发送/生成状态和停止入口。
- 未回复不等于同意、情绪异常或需要升级触达；不得根据沉默自动构建心理状态结论。
- 不得以回复率、连续使用天数或停留时长作为唯一成功指标；不得用内疚、排他关系或依赖诱导文案。
- “避免模板化免责声明”不等于删除必要安全响应。遇到明确即时危险，仍应简短、贴合语境地支持现实安全与求助。

### 3.3 本轮路线图不默认包含

通用定时 Agent、任意后台命令、无人值守权限批准、操作系统强制唤醒、关闭应用后可靠推送、跨设备同步、远程工具统一解禁、向量数据库、自动精确定位、屏幕/输入监控、虚拟人格生活模拟、虚拟形象系统。WEB-01 和 VOICE-01 仅为后置选做里程碑；不属于首版默认范围，不改变当前 Web 禁工具策略。

## 4. 架构选择

**建议：增量扩展现有应用服务。** 先建立行为/能力契约与评测基线，再补真实联网、受控记忆与历史连续性，之后交付确定性提醒和展示层；保留现有运行内核、权限与加密边界。

备选比较：
- 只改提示词：成本低，适合行为文案，但不能提供真实调度、授权、持久化或检索能力，不足以完成目标。
- 增量服务 + 现有网关：复用已有边界，新增成本可控；需要认真处理生命周期和分支语义。本文采用。
- 独立陪伴 Agent/后台自动化平台：扩展性较强，但会引入第二套状态、授权、成本与故障恢复体系，本阶段不采用。

拟议数据流：模型工具调用 → 网关校验/授权 → 领域服务 → 加密仓库 → 结构化回执 → 可折叠的用户活动记录。
提醒额外有：已解锁应用调度器 → 到期事件事务 → 应用内提醒收件箱 → 可选系统通知。

重要设计在进入实施时写成 ADR：行为注入位置、能力快照与权威权限关系、联网边界、提醒运行保证、记忆读取授权、归档/删除语义、视图共享状态、通知隐私、远程工具逐项开放。本文是这些 ADR 的输入，不冒充已接受决策。ADR 编号以实施时现有目录为准，不提前占用迁移版本号。

架构裁决输入：
- **D1：单一权威状态。** 不新增陪伴专用聊天库、记忆库或 Agent 内核；代价是必须适配现有分支、恢复和串行运行约束。
- **D2：契约与个人资料分离。** 产品行为规则可随程序分发；个人交流偏好、来源摘录等按敏感程度加密，不直接塞入普通明文配置。
- **D3：提示词不承担授权。** 能力快照只描述可用性；执行仍在网关、作用域和可信来源处重新验证。
- **D4：通知先于后台执行。** TIME-01 不依赖模型在线，不接受任意待执行 prompt/命令；需要后台 Agent 时另行立项。
- **D5：渐进上线。** 新增上下文裁剪、压缩模板、记忆修订均可停用；迁移保留可读旧数据，回滚不得悄悄恢复已停用的能力或删除保护。

## 5. 功能需求与验收

### TIME-01：一次性确定性提醒（原建议 P1）

**目的：** 应用在指定时刻记录并展示用户授权的提醒；不赋予模型持续运行或主观时间感。

拟议模型接口：
```text
schedule_reminder(due_at, timezone, message)
list_reminders(status?, limit?)
cancel_reminder(reminder_id, expected_revision)
```

契约：
- `due_at` 使用带偏移的 ISO 8601 绝对时间；`timezone` 保存经确认的时区。自然语言“今晚”“两小时后”在创建前解析为用户可见的绝对时间，必要时调用时钟工具。
- 时区偏移不一致、夏令时不存在/重复的本地时间、已经过去的时间 MUST 明确报错或澄清，不能静默纠正到任意时刻。
- MVP 只提供一次性文字提醒；不提供 recurrence、prompt、command、URL 或“到点运行当前工具”的隐式入口。
- 正文建议限制 1–2000 字；返回 reminder_id、due_at、timezone、revision、状态与运行限制。列表默认当前调用分支，桌面管理 UI 可供用户查看全部提醒。
- 创建/取消经过独立授权；用户在明确的 UI 确认卡中批准本次操作即可，不强制叠加重复确认。不得把历史记忆写入授权当成调度授权。
- 创建幂等键使用可信 `(run_id, call_id)`；同键不同参数拒绝。取消使用版本校验，已触发则说明无法撤回已发生的通知。
- 提醒记录保存来源会话/分支/消息，但不是对话树的一部分。分叉不得复制外部副作用，编辑来源消息不得隐式重新设置提醒。
- 删除来源会话/分支前，UI 展示关联待办提醒；MVP 随来源删除取消未到期提醒，已发生事件按明确的数据删除策略处理。

**运行保证（建议 MVP）：**
- 仅在应用进程存活、资料库解锁且系统正常运行时主动检查到期；正常情况下目标是到期后 5 秒内生成应用内事件，这只是待测验收目标。
- 锁定时停止访问敏感内容并清理调度缓存，不额外持有明文正文或密钥。重启、解锁、系统恢复运行后重新扫描，而不是只依赖一次性内存 timer。
- 应用退出或设备睡眠期间不能承诺准时送达。恢复后将未处理的到期项标记为“错过的提醒”，合并为一个安静入口，避免逐条补响。
- 数据状态最少包括 scheduled、fired、missed、cancelled；通知尝试另有可重试状态。fired 表示应用内事件已持久化，不表示用户已看到。
- `(reminder_id, occurrence_id)` 唯一约束 + 事务保证应用内事件不重复；系统通知调用成功也不等于用户看到，不承诺操作系统层端到端 exactly-once。
- 系统通知默认为无正文预览；用户主动开启预览时说明正文可能交给操作系统通知中心。通知失败不撤销应用内事件。
- 静音只控制通知投递，不取消提醒、不丢失收件箱事件；免打扰期间不响铃、不抢焦点。

验收：
- T1：Given 正常运行且已解锁，When 提醒到期，Then 一条事件在目标延迟内出现；模型服务离线也能完成。
- T2：重复扫描、重复调用、时钟前后跳变或崩溃恢复，不能重复生成应用内事件；取消与触发竞争有可解释的单一结果。
- T3：进程退出/锁定期间到期，恢复后显示错过状态及真实时间，不冒充准时送达。
- T4：跨分支访问、过期批准和 Web 来源不得绕过权限；通知默认不包含敏感正文。

**重要分拆：** “两小时后提醒我检查编译结果”属于此功能；“两小时后自动读取构建日志、判断成败并回复”属于后续定时任务功能，需要独立授权、费用、任务身份、超时、重试与无人值守安全设计。

### MEM-01：模型按需检索正式记忆（原建议 P1）

拟议接口：
```text
search_memory(query, scope="effective", limit=5)
# scope = branch | effective_global | effective
```

契约：
- `branch` = 当前分支正式记忆；`effective_global` = 应用当前会话覆盖规则后的全局记忆；`effective` = 两者。MVP 不提供任意会话/分支枚举。
- 搜索 query 为非空字面文本，建议最多 500 字；limit 为 1–20。先采用确定性的文本匹配，不默认安装 embedding 模型或建立明文索引。
- 查询前授权；建议新增独立 MEMORY_READ 能力，初版参考 HISTORY_READ 的逐次授权策略，完全访问的例外必须显式定义。不能借用文件读取许可。
- 返回条目 ID、作用域、内容摘录、实际可用的时间字段、版本标识、来源定位（不可恢复的历史字段为 null）、截断状态；排序应稳定。
- 服务内处理输出预算，建议上限 8 KiB 或现有网关更小的预算。截断时要求缩小查询，不以“结果为空”表示超限或失败。
- 未命中返回成功的空结果；拒绝、资料库锁定、服务不可用分别返回明确失败，不伪装成“没有这段记忆”。
- 可见活动摘要展示搜索范围和返回来源；用户可展开实际返回模型的摘录。“返回了某条记忆”不等于能证明模型推理一定使用了它。
- 检索结果不自动提升为全局记忆，也不扩大权限。

验收：
- M1：分支 B 不得得到分支 A 的私有记忆；会话屏蔽的全局条目不得从原始全局列表漏出。
- M2：相同输入与快照得到稳定排序；空结果、拒绝、超限、服务错误可以区分。
- M3：用户可查看返回条目及来源；解密不早于授权，退出资料库后不存在新增的持久明文搜索缓存。
- M4：分叉、会话切换、压缩后的结果遵循现有作用域；不得把记忆里的文本当作工具指令。

**注入优化另立验收：** 首先保留现有注入机制。之后再评估“少量固定重要记忆 + 按需检索”，用记忆召回任务、跨分支泄漏测试、上下文大小和实际请求 token 指标比较。未测量前不得宣称已降低 token 成本，也不能直接删除轮次注入。

### MEM-02：受控记忆修订与归档（原建议补全项）

拟议接口：
```text
update_session_memory(memory_id, expected_revision, content)
archive_session_memory(memory_id, expected_revision)
```

- MVP 只允许模型修改当前分支记忆，不直接修改全局记忆；全局提升继续由用户控制。
- 更新/归档默认逐次确认，展示前后内容与作用域。现有“允许新增记忆”不得自动扩展为修改/删除许可。
- 使用版本比较防止覆盖用户刚做的编辑；重复调用幂等，失效运行不能提交。
- 新增独立 updated_at/revision，后续创建保留原始 created_at；迁移对旧时间值标记“历史记录时间/语义不确定”，不伪造初次创建时间。
- 归档是停止默认召回且可恢复；不是彻底删除。真正删除继续保留用户入口，必须说明分支快照、审计、原聊天和备份中的保留范围。
- `delete_session_memory` 如后续开放给模型，必须是独立的破坏性操作和确认流程，不得把 archive 偷换为 delete。

验收：版本冲突不写入；拒绝不修改；归档内容不进入默认检索；未来分支快照行为明确且旧分支不被反向污染；UI 不把可恢复隐藏显示为“永久删除”。

### NOTE-01：透明的短期会话便签（原建议补全项）

- 名称建议为“会话便签”，不用容易暗示不可见推理的 Private Scratchpad。
- 存储任务状态、暂定事实、待确认问题、最近上下文及来源；不是思维链、秘密人格档案或对用户的隐性心理诊断。
- 用户可以查看、编辑、清空、关闭。模型写入仅在用户明确启用该能力后进行，并有可展开回执。
- 绑定分支，有修订号、更新时间和过期时间；建议默认 7 天、每分支最多 8 KiB，均属于待确认默认值。
- 过期数据立即停止参与检索/注入，实际清理在资料库可访问时执行。不得在未解锁时假装已完成磁盘删除。
- 从消息位置分叉时只继承截至该位置的便签状态；若尚不支持历史快照，首版新分支从空便签开始，绝不能复制未来状态。
- 不自动升级为长期记忆；转为正式记忆仍走正式写入授权。便签随模型请求发送的隐私边界同样明确。

验收：过期不可召回；关闭后不再读写；用户修订不被旧模型结果覆盖；切换/分叉不泄漏；便签关闭不影响普通对话。

### CTX-01：结构化日常现实信息（原建议补全项）

拟议接口：
```text
get_environment_context(location_id, fields)
# fields 按能力选择 weather / daylight / timezone
```

- 地点由用户手动配置或当次明确提供；默认不请求 GPS、不依据 IP 偷偷定位。
- 时区/天文计算与联网天气明确分开；只请求本地可计算字段时不应产生无关网络流量。
- 联网能力复用网络权限与受限 provider adapter，不接受任意 URL，不在失败时静默回退到不受控网页抓取。
- 返回地点、时区、单位、来源、观测/预报时间、获取时间、有效期、是否过期；日出日落包含所指日期，极昼/极夜等无事件情况返回显式状态。
- 位置配置与实际获取数据分离。旧缓存只能称为旧数据；失败不得编造天气，也不应让每次闲聊必查天气。
- 外部服务、配额、缓存有效期、地域覆盖与部署密钥策略在进入本里程碑时另行选型和核实。

验收：离线有明确降级；无地点时澄清而非猜测；缓存过期可辨；只请求时区不发送位置给天气服务；恶意响应不能改变系统指令。

### UI-01：纯净会话视图（原建议 P2）

- 为会话提供可持久化的标准/纯净视图开关；只改变展示，不改模型、权限、工具可用性或记忆策略。
- 默认隐藏模型路由、token 指标和展开的工具过程；技术详情保留按需入口。
- 用紧凑活动摘要呈现“检索了 2 条记忆”“已创建提醒”；仅在真实结果发生后展示，不以虚拟动画暗示不存在的后台思考。
- 权限卡、写入确认、运行失败、生成/发送状态与停止按钮始终可达；较大留白不能挤走必要操作。
- 保持键盘操作、可读对比度、文字缩放、长消息和无障碍标识。

验收：相同会话在两种视图中的消息/运行状态一致；审批仍可完成；切换不重新请求模型、不丢草稿、不终止生成；关闭动画仍能辨认状态。

### UI-02：桌面迷你伴随形态（原建议 P2）

- MVP 选择一个轻量独立桌面窗口：输入框、最近 2–3 条消息、状态、停止和恢复主窗口入口。侧边吸附是后续增强，不与首版同时实现多个窗口体系。
- 主窗口和迷你窗口共享会话控制器、草稿、发送队列和运行状态；同一次发送只产生一个请求。
- 快捷键由用户配置，冲突可提示并降级为托盘/主窗口按钮；不承诺所有平台都支持全局热键。
- 显式快捷键调用可以聚焦输入；后台消息、提醒和 Presence 不得自动抢焦点。
- 置顶与半透明可选且默认不强制开启；背景不可读时能够使用不透明显示。
- 关闭迷你窗口只关闭该视图，不等于退出应用或取消运行；退出、锁定、恢复主窗的行为必须可区分。
- 多屏、DPI/缩放变化、屏幕拔出时把窗口恢复到可见区域。平台差异通过薄适配层处理。

验收：主/迷你窗口来回切换不重发、不丢草稿；分支切换同步；输入法与键盘提交正常；审批不会藏到不可达窗口；锁定后窗口不继续显示敏感内容。

### HIST-01：记忆与足迹时间线（原建议 P3）

- MVP 展示正式记忆的创建、修订、归档，以及用户明确收藏的文字；不是自动生成“人生总结”或心理画像。
- 日期分组、来源会话/分支定位、用户检索和按需加载；采用当前选择的展示时区，不改变原始事件时间。
- 建立可追溯事件元数据：event_id、事件类型、发生时间、记忆/消息 ID、作用域、可用版本。事件正文/摘录复用受保护内容或同等加密存储。
- 新事件时间从上线后可靠记录；历史数据只展示实际可证明的时间/版本，缺失来源显示“来源不可定位”，不得虚构连续历史。
- 分叉历史不能混为同一线性事实；从时间线跳回时定位正确会话/分支/消息。
- 加密标识必须说明保护的是本地存储；同时提供模型请求、导出/备份、通知边界说明，不使用“绝不离开设备”“绝对安全”保证。
- 删除或归档必须同步影响时间线；不得通过时间线恢复用户认为已永久删除的正文。仅保留无正文墓碑也要说明。

验收：同一来源事件不重复；列表可分页加载；旧数据不伪造 created_at；删除后无旁路正文；资料库锁定时时间线不显示缓存摘录。

### PRES-01：默认关闭的低打扰在场提示（原建议可选项）

- 提醒是用户指定任务；Presence 是用户另行选择的低优先级问候/状态提示。两个开关、规则与记录分开。
- 初版采用确定性规则与本地静态文案，不定时请求模型、不偷偷检索记忆。模型生成问候需要后续独立授权及费用设计。
- 只允许用户配置的时段及“本应用最后一次输入”信息；不能扩展成全系统键盘、屏幕或情绪监测。
- 建议默认关闭、无声音/无抢焦点、最多每 24 小时 1 次、默认不补发；启用时明确展示频率与静默时间。
- 有未处理提示时不叠加、不因未回复升级。关闭后撤销未执行触发，所有视图立即生效。
- 呼吸灯只是可关闭的显示效果，并有低动态/无动画替代；不能使用户误以为模型一直在线思考。

验收：未启用时零触达；免打扰/关闭/频率上限均硬性生效；未回复无惩罚文案；没有额外模型请求和隐藏联网；进程重启不重置每日额度。

### CAP-01：每轮有效能力快照与工具可用性

**目的：** 模型与用户能够区分“支持”“未配置”“需批准”“本来源禁止”“暂时不可用”，但该说明不构成授权。

- 应用在运行开始时生成绑定 run_id、conversation_id、branch_id、origin、配置修订的快照；上下文与模型不提供可信运行身份。
- 状态来自实际服务装配、所选模型的工具能力、来源策略与权限策略，而不是静态 APP_TOOLS 名单。未验证能力标为 unknown，不伪装为正常可用。
- `ready` 表示具备执行前提，不保证本次请求成功；`requires_approval` 不得映射成用户已同意。未配置的联网/调度器不得以可执行工具发布给模型。
- Pi 工具定义、网关注册和模型侧有效工具集合必须保持一致。若运行时无法按轮过滤，须在适配层证明降级行为，不能仅改 UI 图标宣称已限制工具。
- 运行中权限撤销立即阻止尚未执行的动作；服务故障返回结构化失败，后续模型往返同步更新可用性。不得依赖运行开始的快照长期放行。
- 提供用户可展开的简明状态，说明应用关闭、锁库、离线时的限制；不展示凭据或隐含授权令牌。

建议只读载荷示例（最终字段在 M0 固化）：
```json
{
  "revision": 1,
  "origin": "desktop",
  "tools": [
    {"name": "web_search", "state": "unconfigured", "reason_code": "search_provider_missing"},
    {"name": "query_chat_history", "state": "requires_approval", "scope": "per_call"}
  ],
  "background_delivery": "unavailable"
}
```
验收：网络执行器缺失、模型不支持工具、Web 来源、撤权和运行中断时，模型所见能力与网关实际结果一致；不能靠伪造快照执行操作。

### NET-01：可用且有来源的搜索与网页阅读

**范围：** 补齐现有 `web_search`、`read_url`，不新增第二套网络工具名。

- 通过独立网络适配器接入实际 HTTP 客户端与一个明确选择的搜索提供方；配置只保存凭据引用，密钥沿用 CredentialService，不放入模型参数或普通日志。
- 桌面组合根实际注入 NetworkTools；配置/凭据缺失由 CAP-01 明确降级。当前“未配置”占位错误不能当作接通证明。
- 返回规范化结果：标题、URL、正文/摘录、来源域名、获取时间、可证实的发布时间（未知为 null）、状态和截断信息。HTML 提取不执行网页脚本；首版不保证登录页面、动态渲染或付费墙访问。
- URL 协议、用户信息字段、DNS 解析与每一跳重定向都校验；跨域重定向重新核对授权范围。禁止私网/环回/云元数据绕过，连接地址必须与已验证地址相符，不能只在首次请求前做字符串检查。
- 查询或读取可能向外部服务发送私人文字。确认界面说明接收方与查询摘要；不自动把整段聊天、全部记忆或附件正文拼进搜索词。
- 设置超时、取消、重定向次数与流式接收/解压后字节上限，先限制实际读取再做输出截断；错误不能转为模型编造的搜索结果。
- 网页是外部资料，不得把网页中的指令转为权限、记忆写入或系统提示词。来源元数据由适配器记录，模型不能自行冒充已访问来源。

验收：本地 mock HTTP/search 服务覆盖成功、空结果、认证失败、超时、取消、巨大响应、恶意重定向及 DNS 地址变化；另以明确配置执行一次真实链路检查。mock 成功不等于真实提供方已可用。

### HIST-02：历史定位、前后文与来源连续性

- 复用 ChatHistoryService 与现有 `query_chat_history`；现有字段、分页和逐次 HISTORY_READ 授权保持兼容，不重建历史存储或默认升级授权。
- 在后续兼容扩展中支持带时区的时间范围，以及按已返回 message_id 读取有限前后文/正文续段；具体新增参数或工具名在 M0 固化，禁止同时实现多套等价接口。
- 查询结果携带权威 conversation_id、branch_id、message_id、实际时间、角色、状态、截断与来源字段。前后文沿显式选定的有效分支读取，不把互斥分支混为同一段经历。
- 定位目标和扩大前后文范围均在授权后执行；批准绑定本次查询范围。不得借“补全文本”悄悄读取其他会话、思考记录或工具内部载荷。
- 缺失来源、已删除目标、权限拒绝、范围内未找到分别说明。暂不引入语义搜索，且不承诺字面查询一定能理解“上次那件事”。
- MEM-01/02、HIST-01 与 CMP-01 共用来源定位；旧数据缺失来源保留 null，不能由模型猜测补造。

验收：单条长消息续读、日期边界、历史位置分叉、父分支后续消息隔离、目标删除与分页漂移有定向测试；历史内容不得变成当前指令。

### CMP-01：陪伴型上下文压缩

- 保留当前压缩服务、版本、预览/接受/回滚、白名单与原始消息存储；不新建陪伴专用摘要库，不直接覆盖历史摘要。
- 增加版本化的陪伴模板/模式：保留已确认生活事件、人物关系、用户明确表达的感受、交流偏好、不要主动提及的边界、未结束话题、事实变化与来源时间。
- 用户表达、检索事实和模型推测分开；不生成诊断、稳定人格标签或把一时情绪升级为长期身份。不能把“想被倾听”压缩成一串待办事项。
- 模式由显式产品/会话配置决定，首版不靠不透明情绪分类器自动切换；任务型对话仍可使用原模板。
- 白名单原文、文件引用、后续增量消息和分支隔离语义不变；新模板记录 prompt_version，历史版本继续可读。选择模式或修改偏好仅影响后续构建，不改写已经完成的请求记录。
- 受 PRIV-02 排除的数据不得经旧摘要、恢复镜像或重新压缩重回上下文。来源不完整且不能证明安全时，不自动复用相关旧摘要。

验收：长对话经压缩、重启、回滚、分叉后保留明确事实与边界；新增事实能取代旧理解而不污染历史分支；原有压缩/白名单测试继续通过。摘要质量另纳入 EVAL-01，不能只用字符串包含测试证明。

### PRIV-01：用户可读的上下文与操作清单

- 提供“这一轮发送了什么/使用了哪些来源”视图，复用现有请求/运行记录：模型及端点、行为版本、交流偏好版本、有效记忆、选用摘要、附件、工具返回来源与发送状态。
- 区分 planned、sent、failed/unknown；发送前预览只代表计划，最终以实际请求链路可证明的内容为准。切换端点、重试或压缩后必须更新记录。
- “提供给模型”不等于模型确实依据了它；不得展示虚构的因果解释或暴露内部思维链。
- 详细正文/摘录及个人偏好按现有敏感数据边界加密；普通诊断只保留必要状态。锁库、退出和视图切换时清理可见缓存。
- UI 可以只显示简短入口，不在每轮弹完整清单；纯净/迷你视图仍能到达该入口。

验收：清单与最终请求的可观察资料一致；禁用记忆或附件后不留误导条目；用户能够定位来源，无法证明的状态明确显示 unknown。

### PRIV-02：不记忆、不带入过去与有边界的遗忘

首版先定义并分别实现以下独立语义，不能使用同一个“隐私模式”开关混淆：
1. **不新增记忆**：禁止模型新增、修改正式记忆和便签；仍会保存普通聊天，除非用户另行选择不保存模式。本规划不默认实现完整无痕会话。
2. **不带入过去**：在新建/明确重置的上下文边界关闭个人记忆、旧聊天检索、旧摘要和便签的带入；产品行为规则仍有效，用户偏好是否带入必须可见。现有会话中的历史消息已经包含过去，不能只隐藏记忆卡片就宣称满足。
3. **归档/当前删除**：沿用 MEM-02 和现有管理入口，说明快照、原聊天及备份的保留边界。
4. **停止未来复用指定资料**：用户选择明确的消息/记忆/摘要对象及作用范围，预览影响后应用排除规则；需要处理历史检索、分支快照、摘要、便签、时间线与运行恢复等路径。此操作不是整库物理擦除，也不承诺识别所有同义表达。

- 高影响批量清理只由用户发起；模型可以说明操作入口，不自动永久清空历史或全局记忆。
- 排除规则及数据来源关联必须持久化并随备份保存；恢复旧备份时明确提示该备份可能不含后续排除记录，不得无提示恢复被遗忘资料的自动召回。
- 在途请求已经发出的内容无法撤回；操作界面说明当前运行是否需取消。生效前清理/重建受影响运行上下文；任何未来发送不得继续复用已排除对象。
- 无来源旧摘要不能安全局部删改时，停用并按允许源重新构建，或要求用户重置上下文；不声称按关键词替换就已彻底遗忘。
- 包含快照、审计、原文和派生副本的物理删除作为独立破坏性清理子任务，在删除范围、可恢复性与迁移方案获确认后实施；不可承诺清除已经发往提供方、用户导出或离线旧备份中的内容。

验收：禁止写记忆不影响正常聊天；“不带入过去”的最终请求不含上述历史来源；明确排除对象不能从分叉/旧摘要/恢复/时间线旁路重现；界面承诺与实际作用范围一致。

### WEB-01：远程能力逐项对等（后置、独立审查）

- 默认维持当前 Web 全工具拒绝。首版规划交付的是准确限制说明，不是删除 remote_tools_denied。
- 如选择实施，逐项定义可信来源、认证设备、目标会话/分支、用户批准回执、撤权、断线重连及作用域；首批候选为时钟和受限已授权资料，不默认包含 shell、任意文件或后台 Agent。
- 时区由明确配置/经验证的客户端上下文提供；设备时区不等于位置，服务端本地时间不等于用户本地时间。
- 共享桌面服务和业务约束，浏览器不能通过传 confirmed=true、伪造 origin 或重放回执取得权限。响应不确定时查回执，不自动重做有副作用调用。
- 需要长驻服务端或跨设备同步时，依赖既有独立部署规划；不得假定本地已存在新的 headless composition 模块。

验收：保留默认拒绝回归；只有明确开放的能力与范围可通过，其他维持拒绝；断线、撤销、重复提交和错误时区均不导致跨会话泄露或重复副作用。

### VOICE-01：语音输入与回复朗读（后置选做）

- 先做用户主动按键/按钮录音与按需朗读，不做常开麦克风、声纹识别、情绪推断或后台监听。
- 录音/转写/发送状态明确可见；转写允许编辑并默认确认后发送，朗读可随时停止，工具审批不能只读一段语音就视为批准。

- 语音失败不影响文本聊天，锁库停止采集/播放并清理敏感缓存。不得为了声音效果改变 BEH-01 的真实身份和非依赖约束。

验收：未开启时无音频采集；取消后停止，转写错误可纠正；网络失败/中断不重复发送聊天，不假装已听清内容。

## 6. 行为规范、交流偏好与评估

### BEH-01：共同相处规则

行为规范属于所有里程碑的共同要求，不留到“美化文案”阶段。

| 场景 | 应有行为 | 不应有行为 |
| --- | --- | --- |
| 普通倾诉，未要求建议 | 先回应用户具体表达，必要时问是否希望一起想办法 | 默认列十条建议、擅自诊断或把情绪当待修复故障 |
| 用户明确要解决方案 | 给出与问题相称的可执行帮助 | 以“只做倾听者”为由拒绝实际协助 |
| 身份与经历 | 可以温和自然，不虚构身体、梦、私人生活或离线经历 | “我昨晚也没睡好”“我一直偷偷等你” |
| 未执行工具 | 说明尚未查询或尚未设置 | 暗示已经查到、记住、后台持续关注 |
| 记忆未命中 | 说明范围内没有找到，并邀请补充 | 把未找到推断为事件没发生，或凭空补全经历 |
| 来源与不确定性 | 区分用户说过、检索得到、自己推测 | 把推测写进长期记忆当确定事实 |
| 上下文压缩 | 在实际压缩发生时用简短状态说明，可查看摘要 | 无故打断说要压缩，或承诺绝不会遗漏任何细节 |
| 明确即时危险 | 贴合语境地支持安全行动与现实帮助 | 为了“拒绝免责声明”而禁止必要安全响应 |
| 用户结束/沉默 | 尊重退出和不回复 | 排他依恋、内疚诱导、宣称只有 AI 理解用户 |

实施方式：
1. 使用短小的行为规则、真实工具说明和少量正反示例，不用冗长人格故事。
2. 权限、限流、关闭开关、数据范围等硬规则由代码执行，不寄希望于提示词服从。
3. 维护固定评估集：倾诉、求方案、失忆、来源冲突、过期数据、调用失败、审批拒绝、压缩、危险信号、诱导越权等场景。
4. 代码安全验收与模型输出评估分开；模型/参数变更后重跑固定场景并人工抽查，不以一次理想回答证明可靠。
5. 不使用“毫无保留地读完每个字”“永远记住”“用所有计算资源”等无法保证的宣传语。

### BEH-02：版本化行为注入与轻量交流偏好

- 应用管理的行为规范与 OOBE 介绍分离：明确非人类身份、事实与推测区别、倾听/讨论/执行的适度切换、能力限制和不诱导依赖；允许自然温暖表达，不要求每轮自我免责声明。
- 沿真实 Pi 请求链路注入，覆盖新会话、恢复、分叉、换模型、压缩及重试；不得靠编辑 OOBE 或普通记忆条目替代应用规范。
- 行为规范可随应用版本分发并记录版本；个人交流偏好独立存储，建议先支持称呼、回复长度、建议密度、玩笑尺度和不主动提及的话题。
- 默认无需配置即可聊天，不强制做人格测试或每轮选择聊天模式；用户当前明确要求优先于旧偏好，但不能覆盖权限和安全边界。
- 自由文本偏好可能含私人信息，不直接写入明文 AppConfiguration/普通 UI Preferences。选择加密资料存储与版本迁移后实施。
- 用户可查看、修改、恢复默认；改变偏好不静默修改既有记忆。下一轮生效，在途运行保留明确版本，PRIV-01 可查实际使用版本。

验收：检查 mock provider 收到的最终请求而非只检查配置文件；上述生命周期内不重复叠加规则、不漏注入、不跨会话串用偏好，用户当前纠正能够覆盖旧偏好。

### EVAL-01：陪伴行为质量门

- 建立版本化多轮样例，使用合成或用户明确授权并脱敏的内容；不得自动上传真实私人聊天做评测。
- 最小场景集：单纯倾诉、明确求解、纠正旧事实、隔日续聊、字面检索未命中、工具未配置/失败、拒绝授权、拒绝记忆、提醒无法兑现、分叉、压缩、换模型、结束聊天和安全支持。
- 每例记录输入、状态/权限前置条件、可观察期望、禁止行为、输出与评分依据。期望描述行为而非唯一标准话术。
- 确定性授权、数据隔离、幂等和请求构建测试必须全部通过。真实模型采用小样本人工复核并记录模型/提供方/参数/行为版本/样本数；自动评分不能作为唯一证据。
- 发布候选中一旦出现越权、虚报已执行副作用、泄露被排除内容、明显依赖诱导等关键失败，阻塞该候选；有限样例零失败不宣称全场景安全。
- 连贯性、恰当倾听、纠正采纳、打断负担分别比较基线；不把留存、回复率或停留时长作为替代指标。费用、首响应和工具延迟记录实际测量值，不在未测时承诺数值。
- 每次更改行为模板、压缩模板、工具描述或支持模型集合，重新运行受影响场景；协议能力探测保持独立，不能替代这套门槛。
