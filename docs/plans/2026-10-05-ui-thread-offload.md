# UI Thread Offload Implementation Plan

**Goal:** 修复 UI 线程阻塞审计中的同步业务入口，保留现有未提交功能和安全边界。

**Architecture:** 复用 ConversationProcess 处理会话持久化；通用受控后台任务处理文件/工具/维护操作。GUI 只读取控件值和应用结果，异步结果按代次/会话校验；取消等待必须等待已提交写入结束，退出先关闭任务再关闭资料库。不整体改写同步业务服务，不降低密码学参数。

**Tech Stack:** Python 3.12+, PySide6, qasync, concurrent.futures, SQLite, pytest-qt.

## Steps
1. 新增后台任务生命周期与 GUI 回调适配器，测试心跳、异常、取消和关闭。
2. 工具执行及授权后台化；搜索防抖/代次丢弃；外观预览去掉重读历史。添加针对入口的回归测试。
3. 附件导入/发送/显示后台化，快照控件输入并阻止重复提交，保留异步会话有效性校验。
4. 扩展会话进程的 fork/retry 操作，后台返回预构建历史；测试分支语义和写锁响应性。
5. 后台执行导出、备份恢复、外观资源导入、安全恢复、压缩及重型面板读写；维护退出等待。
6. 配置读取缓存/失效与低频同步入口归口；运行完整测试、ruff/mypy 和隔离性能探针，修复回归。

每步先增加针对性测试，再实现并回归。现有工作区包含未提交改动，不切换工作区、不自动提交。

## Execution outcome
