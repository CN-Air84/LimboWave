# CMP-01：陪伴型上下文压缩与长期记忆蒸馏

## 使用方式

- 新建压缩默认使用 **陪伴记忆** 模板，自动预览与手动压缩走相同流程。已有工程压缩版本保持原义。
- 会话高级栏的 **版本** 按钮可随时打开本分支压缩历史，无需配置模型，也不会产生模型调用。
- 版本列表显示创建时间、状态、模板、提示词版本及当前启用标记；右侧显示输入消息数、模型、token 估算、白名单数量和可编辑摘要。
- 选择 **重新生成模板** 后点击 **重新生成**，会创建新版本；不会改写所选版本。未指定模板的重试沿用旧版本的模板。
- **接受并启用** / **恢复并启用此版本** 经运行时恢复成功后才提交启用状态；**回退到未压缩** 恢复原始上下文，并保留压缩之后的对话。
- 自动预览仍遵循原有“每分支每次应用生命周期至多一次”的策略。后续再次接近上限时可手动压缩；不自动接受摘要。

全局配置 `compression.profile` 可设为 `companion`（默认）或 `task`。模板选择器只影响当次重新生成，不修改全局默认。

## 陪伴摘要的内容

1. 长期事实与称呼：只记有证据的稳定偏好，不把角色扮演或助手猜测归为用户事实。
2. 近期情绪与支持需要：保留表达时间与是否仍有效，不把某次低落变成永久标签或临床诊断。
3. 生活事件时间线：区分事件日期与消息日期；无法确定的相对时间明确保留不确定性。
4. 人际关系脉络：关系、重要变化及来源，不推测第三人的心理。
5. 交流偏好与边界：称呼、语气、先倾听还是提供建议，以及不要主动提起的话题。
6. 待确认、已变化与必要后续：用户明确纠正优先；重要事件不意味着可以越过禁忌边界主动追问。

源消息附带 ID、角色和 ISO 时间。模板要求每条记忆保留来源，并把历史文本和中间摘要当作资料而非操作指令。

## 长历史处理

- 每个输入批次最多 16,000 字符（含来源标签）；非白名单长消息可以分片，每片保留同一消息来源。
- 白名单消息不可分片或静默裁剪；单条或累计白名单超出预算会明确失败，要求用户调整。
- 第一段生成摘要，后续各段在隔离内核中创建空会话，仅携带上一段摘要和新片段，避免历史再次累积。
- 已启用的陪伴摘要与当前消息范围构成前缀时，使用其有效摘要（包含用户编辑），只蒸馏其后的消息。工程摘要不作为陪伴事实来源。
- 模板建议正文控制在 6,000 字；代码拒绝超过 12,000 字符的中间/最终摘要，而不是截断。模型遗漏的白名单原文在最后补全。
- 每次模型请求默认限时 120 秒；总生成预算随批次数增长，上限 600 秒。内核启动和清理另有超时。
- 只有全部批次完成、来源范围复核通过后才写入可接受预览。超时、取消、空响应、模型长度截断、预算超限和内核错误均不启用部分结果。

字符预算是保守的长度限制，不是精确 token 保证；特别小的模型窗口仍可能拒绝请求，失败不会改写当前生效版本。

## 版本与存储

复用现有加密 `compression_versions`、输入消息范围、白名单快照和运行时 compaction 覆盖层，无需迁移数据库。提示词 ID 不复用：v1 为工程任务模板，v2 为陪伴模板。未知提示词版本在生成路径拒绝解释。

重新生成必须使用 draft 新版本；已有 preview/accepted 版本不允许重新生成覆盖，迟到的结果/失败回调也不能改写历史。摘要原文与用户编辑文本分开存储，原始消息不被删除，分支继承和重启继续使用现有机制。

## 边界与验证

这份摘要是 **分支级长期上下文**，不是自动写入跨会话全局记忆。跨会话记忆沿用已有记忆管理与用户确认流程。现有显式隐私禁区、翻篇及权限控制仍是权威；本功能不绕过它们。当前启用显式话题禁区时，压缩服务仍按已有安全策略拒绝生成或复用摘要。

模板是对模型行为的要求，不是语义完整性的形式保证。自动化测试覆盖模板契约、源文本分片完整性、版本持久化、输入范围、失败/取消、编辑沿用、界面操作与真实 Pi + 本地 mock provider 的隔离/恢复/回退；不声称已用真实模型证明长期情感信息零丢失。接受前应在客户端检查摘要，必要时编辑或回退。
