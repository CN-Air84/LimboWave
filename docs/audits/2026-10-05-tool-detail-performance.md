# 单个工具步骤详情展开/收起性能

## 原因与改动
- 原实现从工具区 LayoutRequest 回调再次 invalidate 同一个布局，并无条件向父级提交 updateGeometry，产生重复布局请求；暂停动画后也会继续测高。
- 原详情高度只缓存最后一个宽度，Qt 交替探测建议宽度和实际宽度时反复排版长文本。
- 本次仅修改工具步骤展示组件：取消布局反馈循环；缓存最多 4 个宽度和静态 sizeHint；收起时返回零高度而不测量不可见文字；高度动画不再重复设置自然高度文本的几何。
- 详情使用可选取的纯文本 QLabel 布局，便于复用文本排版并复制内容。实时结果、字体、样式变化会使缓存失效。
- 保留原有 220ms 可反向动画、独立展开状态、完整审计数据、全局显隐与禁用动画的回退行为。没有新增截图动画、后台服务或持久化字段。

## 验证
- 相关 UI 回归：161 passed（工具步骤、全局显隐、聊天视图、历史加载、思考区）。
- Windows 原生 Qt：48 passed。
- 新增 6 项确定性回归：多宽度缓存、布局请求收敛、可选取的纯文本、文本/字体更新失效、隐藏详情不测量、动画中实时更新。
- Ruff、Mypy、git diff --check 通过。
- 已检查收起、展开 50%、展开完成、收起 50% 四种视觉状态。
- 本轮未重跑整个项目测试；上轮全量回归的其他模块限制仍见 2026-10-05-tool-step-performance.md。

## 固定视口合成探针
12 个工具步骤，其中一个约 16k 字符的长详情；固定 900×700 滚动视口；6 次展开/收起，共 78 个手动推进的动画帧。两组都启用 cProfile，每帧处理 Qt 事件并强制截图，因此包含额外绘制开销，不等同于实际应用帧率。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 工具区测高次数 | 3002 | 525 |
| 长详情文本测高次数 | 397 | 10 |
| 帧处理中位耗时 | 21.59 ms | 12.65 ms |
| 帧处理 P95 | 42.13 ms | 22.41 ms |

本机测试数据仅用于相同负载对比。脚本、剖析输出、JSON、视觉核对图和测试日志位于 .var/tool-detail-performance/。
