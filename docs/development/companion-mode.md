# 桌面迷你陪伴模式

## 使用

- 点击对话区右上角胶囊的左侧气泡 **迷你陪伴**，或在应用内按 **Ctrl+Shift+M**，进入独立小窗口。再次按应用内快捷键返回完整界面。
- 窗内没有标题栏或独立底部工具栏：收起/主界面/选项按钮悬浮在消息流上，附件/停止/发送按钮位于输入区内。删除作者称呼前缀与常驻快捷键提示；用户消息使用右对齐、按正文长度自适应的气泡。
- 小窗口展示当前会话最近三条消息气泡、运行状态和轻量文字输入。**Ctrl+Enter** 发送，**Enter** 换行。生成时显示 **停止**；允许排队时按钮变为 **排队**，沿用原有发送队列规则。
- **收起 / Esc** 折叠成迷你条，点击 **展开** 恢复输入。**主界面** 或关闭按钮恢复原主窗口，不退出程序，不自动取消生成。
- **...** 菜单可开关置顶、半透明和全局呼出。置顶与半透明默认关闭；不透明显示始终可选。
- Windows 首次进入迷你模式时尝试注册 **Ctrl+Alt+Space**。在别的程序里按它可呼出并聚焦输入；迷你窗口已在前台时再按一次收起。可在菜单中修改或禁用此快捷键，设置仅对本次运行有效。
- 全局热键冲突会显示提示，原有有效绑定保留。没有原有绑定或当前平台不支持时，右上角胶囊入口和应用内快捷键仍可用。不会拦截或替换其他程序已占用的热键。

右上角胶囊合并了两个独立入口：左侧气泡打开迷你陪伴，右侧书页切换倾诉模式（Ctrl+Shift+F）。悬停或键盘聚焦后展开为「迷你陪伴｜倾诉模式」，Tab / Shift+Tab 在两侧切换，空格激活。进入迷你陪伴不会清除倾诉状态，返回主界面后仍保留。侧栏不再重复放置迷你入口。

## 状态与隐私

- 两个输入框绑定同一个 `QTextDocument`，共享草稿和撤销历史；不建立第二个会话控制器，不额外请求模型，不把草稿写到设置文件。
- 历史预览/分支切换会重新绑定当前视图的草稿。文本、编辑旧消息状态、附件和队列状态沿用主界面；撤回队列、错误重试等详细操作请返回主界面。
- 点击输入区内的「附件」选择文件，也可粘贴文件/图片或拖入本地文件。附件条显示文件名、缩略图并支持移除，与主界面共用同一份附件草稿。支持类型与主界面一致（TXT、Markdown、DOC/DOCX、JPG、PNG；不扩展 PDF 支持）。图片发送仍要求模型具备视觉能力。
- 媒体粘贴复用原输入框的异步编码及草稿代际检查；普通文字粘贴使用迷你输入框当前光标。文件选择框挂在迷你窗口上，选择完成后再次检查会话与草稿，避免把过期选择导入新草稿。只读预览/加载中/不可用状态不能绕过附件限制；带附件或编辑旧消息不支持排队的限制保持不变。
- 主界面隐藏时会暂停其流式文本渲染。迷你视图读取已接收但未渲染的片段，不消耗缓冲，不强制刷新整段隐藏对话，因此仍可持续看到回复。
- 后台消息刷新不会聚焦或激活窗口。权限/确认面板出现时恢复主界面，但不主动调用窗口激活；已有待确认面板时拒绝进入迷你模式，不自动批准操作。
- 打开设置、登录/锁定等全页时关闭迷你投影并注销全局热键；返回工作区后可重新进入。隐藏或关闭迷你视图会解绑草稿文档并清除消息预览，不删除原草稿/对话。
- 程序退出的原有关闭守卫仍然生效；只有确认允许退出后才清理迷你窗口和热键。

## 实现边界

- `src/limbowave/ui/companion_mode.py`：只读展示适配、现有命令转发、窗口生命周期、权限面板可达性。对现有 ChatView 的私有展示字段依赖集中在此，未改变业务层。
- `src/limbowave/ui/companion_window.py`：原生可拖动/缩放窗口、最近三条纯文本预览、共享文档输入、迷你条、主题样式和屏幕可见区域校正。
- `src/limbowave/ui/companion_hotkey.py`：Windows `RegisterHotKey` / `WM_HOTKEY` 薄适配，冲突和注销处理；测试/非 Windows 后端不注册原生热键。
- `src/limbowave/ui/main_window.py`：初始化、全页隐藏和通过退出守卫后的清理三个接入点。历史预览通过现有 `currentChanged` 信号重绑定。

窗口显示、屏幕增加/移除、可用区域变化时校正位置，支持负坐标屏幕；可用高度不足时收起为迷你条。首版不包含边缘吸附、系统托盘、开机自启、跨重启保存窗口偏好或非 Windows 全局热键。长消息预览有长度上限，完整 Markdown、工具步骤和历史保留在主界面。

### 启动入口修复（2026-10-26）

用户反馈：侧栏按钮和 Ctrl+Shift+M 均无反应。已复现：实际启动时 `_wire()` 使用 qasync `run_until_complete()` 启动 IPC；这段临时事件循环结束也会发出 `QApplication.aboutToQuit`。原接线把该信号直接连接到永久性的 `CompanionMode.shutdown()`，导致正式主循环尚未开始，`open()` 就已被 `_shutdown` 守卫永久阻断。

修复：临时循环结束只释放原生热键；只有通过主窗口关闭守卫的真实关闭才永久停用 companion。Qt 信号接收器保留在 QObject 控制器上，避免窗口销毁后残留非 QObject 回调。

新增 `tests/ui/test_companion_startup.py`：独立进程内运行真实 qasync 启动循环两次，再实际鼠标点击入口或发送 Ctrl+Shift+M 按键，检查打开、返回及最终退出。旧实现可稳定复现失败；修复后两个入口均通过。以前的 pytest asyncio 接线夹具绕过了这段 qasync 启动流程，这是上一轮测试漏检的原因。

本轮验证：启动入口、迷你模式、热键、关闭守卫和启动面板相关测试共 **42 passed**；Ruff 与 scoped mypy 通过。当前运行中的进程不会自动热更新，需要重新启动源码应用加载修复；没有强制关闭用户应用或修改聊天数据。
