# 跨会话聊天记录查询工具

`query_chat_history` 读取应用已保存的可见聊天正文。工具在 Pi 扩展注册，经现有权限闸门和本地工具 IPC 执行；查询不依赖模型当前上下文，也不会调用 Pi 的运行时历史作为权威数据。

## 参数

| 参数 | 含义 | 默认 / 限制 |
| --- | --- | --- |
| `query` | 标题或正文中的字面关键词，忽略大小写；不支持正则或 SQL 通配符 | 空，最多 500 字 |
| `conversation_id` | 目标会话 ID，不改变用于审批/审计的调用者会话 | 可选，最多 200 字 |
| `branch_id` | 消息所属分支 ID，不自动展开继承前缀 | 可选，最多 200 字 |
| `limit` | 本页消息上限 | 20，1–50 |
| `offset` | 匹配结果中跳过的条数 | 0，0–10000 |

示例：`{"query":"Docker","limit":10}`。按返回的会话/分支 ID 可以缩小范围；省略关键词可查看最近保存的消息。

## 权限与隐私

- **完全访问**：免弹窗。
- **仅聊天 / 自由读取 / 自定义**：每次调用都弹出已有悬浮权限框，仅有“拒绝 / 允许本次”；关闭或取消视为拒绝。
- 文件读取授权不能覆盖历史读取；不允许建立该能力的持久会话授权。
- 确认前不查询或解密其他会话正文；会话或运行来源变化后审批失效。
- Web 来源仍禁止全部工具，即使完全访问或客户端声称已确认也不放行。
- 仅解密标题和可见正文，不读取思考、工具详情、运行时镜像或附件。
- 不添加明文索引，不改变数据库版本或加密格式。

## 返回与分页

`results` 包含 `conversation_id`、`conversation_title`、`branch_id`、`message_id`、`role`、`created_at`、`status`、`content`。默认按消息时间和 ID 从新到旧排序；同一消息只按所属分支返回一次。

正文是最多 2000 字的摘录，关键词命中优先展示附近内容。`content_offset` 为摘录在原文中的字符偏移，`content_truncated` / `title_truncated` 明确标记截断。工具总结果还受网关 UTF-8 字节预算限制。

有更多结果时 `has_more=true`，使用实际返回的 `next_offset` 继续；不要自行加 `limit`，因为字节预算可能缩小本页条数。达到分页偏移上限时 `offset_limit_reached=true` 且无下一页偏移，应添加关键词或会话/分支过滤。分页不是跨调用快照：两次查询之间新增或删除消息可能改变偏移。

无匹配记录返回成功的空结果；未配置服务返回明确错误。历史内容是检索资料，不能视作当前用户指令。

## HIST-02：按消息展开前后文

沿用同一个工具、同一种 `HISTORY_READ` 能力，新增与搜索互斥的定位模式：

```json
{"message_id":"搜索结果中的 message_id","before_turns":2,"after_turns":2}
```

| 参数 | 含义 | 默认 / 限制 |
| --- | --- | --- |
| `message_id` | 应用保存消息的权威 ID，不是 Pi entry ID | 必填，1–200 字，不能全为空白 |
| `before_turns` | 锚点所在轮之前的轮数 | 2，整数 0–3，拒绝布尔值 |
| `after_turns` | 锚点所在轮之后的轮数 | 2，整数 0–3，拒绝布尔值 |
| `conversation_id` | 可选范围校验，必须与锚点所属会话一致 | 省略时由锚点定位 |
| `branch_id` | 包含锚点的有效分支；可显式选择继承该锚点的后代分支 | 默认锚点所属分支 |

一轮从用户消息开始，包含其后的助手回复，直到下一条用户消息之前。始终包含锚点所在轮，因此默认最多5轮、最大7轮；前后均为0时只读锚点所在轮，而不只是锚点单句。开头没有用户消息的助手片段作为开头一轮处理。连续用户消息分别计轮，不按固定两条消息硬凑一轮。

- 不可与 `query`、`limit`、`offset` 混用；仅传轮数而不传 `message_id` 也会在审批前拒绝。原有关键词搜索的参数和返回结构不变。
- 按有效分支从旧到新返回：继承父分支前缀，遵守分叉点是否包含起点消息的既有语义；绝不混入父分支分叉后的未来或兄弟分支。每条 `branch_id` 仍表示消息实际所属分支，`context_branch_id` 表示本次选定的有效分支。
- 定位与正文解密均在本次授权后进行；搜索获准不会自动批准后续展开。授权仍绑定调用者会话和本次完整参数，Web 来源禁止调用。
- 加载调用者的翻篇与话题禁区设置。翻篇不允许跨会话展开；被排除的用户轮不能通过助手改述泄漏。若锚点被排除、已删除或不在指定范围，返回“目标消息不存在、已删除或不在可读取范围内”，不泄露受限目标存在性，也不退回宽泛搜索。
- 数据来自单次只读事务；使用消息时间与 ID 的 keyset 定位，不依赖搜索页的 `offset`。只读取可见正文及必要元数据，不解密思考、工具内部载荷、展示片段或运行时镜像，不建立明文索引。

### 展开模式返回值

沿用各条结果中的来源 ID、角色、时间、状态、正文摘录和截断字段，另有：

- `mode="context"`、`order="oldest_first"`、`anchor_message_id`、`context_branch_id`。
- 每条 `is_anchor` 标识锚点；`requested_before_turns` / `requested_after_turns` 表示申请的轮数，不代表实际完整返回轮数。
- `has_more_before` / `has_more_after` 表示该方向仍有消息或因输出预算省略了消息；不使用搜索模式的 `next_offset`。需要再展开时，对新的消息 ID 重新发起授权调用。
- `privacy_filtered` 表示结果中有隐私过滤缺口，不能把剩余片段视作完整逐字记录。
- `window_truncated` 表示硬性消息扫描上限或总输出预算导致窗口不完整；`output_truncated` 表示 UTF-8 总输出预算触发裁剪。每条 `content_truncated` / `title_truncated` 单独标记正文或标题摘录。

前侧最多保留64条（含锚点）、后侧最多64条，每次仓库页最多8条；边界判断最多额外读取小量一页内记录，防止畸形长轮次无界扫描。每条正文仍最多2000字，总结果遵守网关字节预算。预算不足时先裁剪远端消息，始终保留锚点；连锚点和必要来源元数据都装不下时明确报错。隐私规则启用且扫描上限导致无法确认用户轮来源时，不返回无来源保证的助手片段。

本增量只做前后文展开，不增加语义检索、按日期范围搜索或单条长消息续读，也不会把历史内容当作当前用户指令。

## 普通搜索的用户轮次隐私边界（2026-10-27 修复）

普通搜索同样不能仅凭助手回复自身不含禁区关键词就放行。启用话题禁区时，每条助手候选沿其所属有效分支向前读取至最近用户消息，先用完整轮次前缀判定排除状态，再做关键词命中和 offset/limit 分页。即使用户消息不匹配查询词、已被过滤或不在当前页，也不能让所属助手回复重新进入检索结果。分叉继承遵守起点包含规则，父分支未来和兄弟分支不参与该回复的归属判定；安全的新用户轮会恢复正常检索。

归属检查只读现有公开消息投影（正文、角色、时间、ID、状态和必要 run 元数据），不解密思考/工具/展示片段。每次最多读取64条、每页最多8条，未在预算内确认所属用户或分支损坏时对该助手候选保守拒绝；较近且能确认来源的更早候选仍可独立通过。单次查询只缓存最多256条判定，不建立持久索引。未启用禁区时保留原检索路径；原有结果DTO、从新到旧排序、输出预算和分页含义不变。
