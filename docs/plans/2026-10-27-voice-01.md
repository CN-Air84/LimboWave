# VOICE-01 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add opt-in desktop push-to-talk, editable transcripts, interruptible on-demand speech, and encrypted API configuration with a local-service extension boundary.

**Architecture:** Keep voice configuration separate from model routing and browser DTOs. Domain settings and an async provider protocol isolate the OpenAI-compatible HTTP adapter from future native Whisper/system implementations. Qt captures and plays in-memory audio; a cancellable desktop controller never submits messages or approves tools.

**Tech Stack:** Python, PySide6 QtMultimedia (lazy loaded), httpx, pydantic, existing encrypted CredentialService, pytest/pytest-qt.

---

### Task 1: Configuration and credentials
- Create `src/limbowave/domain/voice.py` and `src/limbowave/application/services/voice_service.py`.
- Add domain/provider/configuration tests in `tests/unit/test_voice.py`; run them before implementation.
- Store non-secret config in `voice.json`, keys only in the existing encrypted vault. Defaults off; independent STT/TTS enablement; no implicit reuse of model credentials.
- Reject credentials in URLs, query strings, redirects and non-HTTPS external URLs. Local mode accepts loopback only; no fallback to an external provider.
- Preserve other application settings. Changing service address must not forward an existing key to a new host.

### Task 2: API adapter and local boundary
- Create `src/limbowave/infrastructure/voice_api.py`.
- Implement multipart `/audio/transcriptions` and WAV `/audio/speech`, with request/response limits, bounded timeouts, cancellation and sanitized errors.
- Add mock-transport tests for URLs, payloads, authorization, errors, cancellation and limits. No paid/live requests in tests.
- Local compatible servers use the same protocol; native engines later implement `VoiceProvider` without changing chat UI.

### Task 3: Settings UI
- Create `src/limbowave/ui/voice_settings.py`; lazily register in `src/limbowave/ui/settings_panel.py`.
- Provide API/local selector, base URL, model, masked key (blank preserves), explicit delete, voice and speed. Save gives inline feedback and clears password fields.
- Disclose audio/text upload and AI-generated voice before opt-in; original audio is not persisted by LimboWave and provider retention is independent.

### Task 4: Desktop voice lifecycle
- Create `src/limbowave/ui/voice_audio.py`, `voice_controls.py`, `voice_controller.py`.
- Add primary-chat controls in `src/limbowave/ui/chat_view.py`; wire services/lifecycle in `src/limbowave/app.py`.
- Hold records, release transcribes, success appends to the current draft only. No automatic sending or auto-reading.
- Stop/Escape cancels capture, upload or playback. Switching chats/pages, losing capture focus, shutdown and vault unavailability invalidate callbacks and clear audio buffers.
- Bound recordings to 60 seconds; reading uses the latest completed assistant body, not tool/thinking content.

### Task 5: Verification and documentation
- Add `tests/ui/test_voice_ui.py` using fake audio/providers, test all state transitions, error recovery, stale results, keyboard hold and settings/key behavior.
- Run targeted suites, architecture boundaries, Ruff and mypy. Inspect a rendered settings screenshot and composer at desktop/narrow widths.
- Document configuration, local deployment contract and manual microphone/playback checks in `docs/development/voice.md`.
- Preserve unrelated in-progress workspace changes; do not commit or stage them.
