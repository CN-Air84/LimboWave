# 翻篇与话题禁区（PRIV-02）

入口：桌面端 **会话记忆 → 翻篇与禁区**。全局记忆设置也可以管理话题禁区。

## 翻篇聊

“翻篇聊 · 不带入过去”创建一个独立、持久保存的新会话，不删除、覆盖或归档原聊天。

- 不自动带入全局个人记忆、其他会话的聊天、旧便签、旧附件和旧摘要。
- 可以继续使用新会话内的正文、新附件和新积累的本会话记忆。
- 产品系统规则、模型选择及权限规则仍有效；全局个人偏好不会作为记忆注入。
- 这不是无痕模式，也不是“不新增记忆”模式。消息仍会保存。
- 翻篇状态跟随会话和它的分支，重新打开、重试及运行恢复不会解除。

## 话题禁区

规则作用于整个当前资料库，可以填写话题、每行一个关键词／别名，以及可选的明确消息／记忆 ID。
匹配使用 Unicode NFKC、大小写折叠和空白归一化，不是模型分类器；明确来源还绑定正文指纹，
防止相同正文换一个 ID 后复活。规则可以解除，但解除后相关历史可能重新被自动复用。

应用会在记忆注入、记忆检索、聊天检索、工具返回、标题候选及最终模型上下文中执行边界。
命中的**整条**资料被排除，不是把关键词替换后继续发送其余内容。
用户本轮主动输入的话仍会发送；涉及禁区的这一轮不能让模型另存一条无来源的记忆。

### 为保证安全而采用的保守限制

现有历史资料没有完整来源关系，因此不能承诺仅删除一个关键词就能排除所有间接关联：

- 有禁区时，规则建立之前（以及同一时间戳）的记忆和助手回复不自动复用。
- 无来源便签、旧摘要、运行时工具痕迹、隐藏思考和旧图片不作为历史注入来源。
- 有禁区时不生成压缩摘要。受保护会话发送时使用允许的原始正文，不能应用旧摘要，Pi 原生自动压缩也被禁止。
- 检索不把无来源会话标题带给模型；界面中的原标题与历史记录仍完整保留。
- 不承诺识别所有同义表达、暗指或用户未列出的关联，也不能阻止模型凭自身知识猜测。
- 这不是物理擦除；不清除已经发送给提供方的内容、用户导出文件或离线旧备份。

## 生效、存储与恢复

修改规则前必须停止当前回复并等待收尾；压缩／标题生成期间也不能改规则。
规则正文和来源指纹使用现有资料库密钥加密，存于 SQLite 的 `memory_documents`，随 `.lwb` 备份保存。
规则读取／解密／校验失败时禁止发送或工具调用，不静默恢复为无规则状态。

恢复旧备份会恢复该备份时点的规则，可能缺少后来新增的禁区。恢复确认框会提示这一点；
请在恢复后先核对禁区，再发送消息。保留的恢复前资料库仍可用于找回后来的规则。

## 实现边界

每次发送／重试都从应用权威消息重建允许复用的历史，不信任 Pi 的恢复镜像或原生压缩。
扩展的最后一个 `context` 钩子替换历史前缀，保留明确的本轮输入；出站钩子核对重建成功标记，
失败时显式中止，而不是依赖扩展抛异常（Pi 可能吞掉扩展异常）。不支持此边界的内核拒绝发送。

Web 端没有新增管理入口，仍保留远程工具默认拒绝；通过共享运行链路续聊时仍执行已保存的规则。
原始历史查看／手动导出属于用户主动访问，不受自动复用过滤影响。


## 网络外发与结构化工具结果（2026-10-27 交叉复核修复）

- 所有 `Capability.NETWORK` 工具在执行前检查参数，包括搜索词、网页地址、环境查询地点和经纬度；命中禁区即拒绝，尚未解析凭据、执行搜索器或发起 DNS/HTTP。普通审批和 FULL_ACCESS 不解除禁区。
- 本版没有新增“本轮主动提及即允许联网发送”的放宽路径：即使用户主动提及，命中的网络参数仍被阻断。用户消息发送与工具外发是两种不同动作。
- URL 检查原文及有界百分号解码、查询 `+` 解码、路径/查询值和 Unicode/IDNA 主机视图。检查副本只用于拦截，不改变原授权目标。超过解码/结构预算或无法安全解析即拒绝，不尝试猜测。
- 网关在实际同步执行线程内安装 `guard_network_request(check_url)`；NET 传输每跳在 DNS 前调用检查，包括同源和跨源重定向。作用域嵌套只能叠加约束，正常、异常退出都恢复上一层检查器。
- 传输 URL 可能携带搜索服务 API key。拒绝仅返回常量错误，不回显 URL、密钥、禁区词或原始异常；本次测试只使用本地 mock/stub，无真实密钥或收费调用。
- 工具结果按结构递归检查字典键值、列表/元组文本、错误、notes、明确来源 ID 及完整正文指纹。命中后拒绝整条结果，不以删字段制造“安全”结果。循环、非支持类型、非法编码、非有限数值及预算耗尽也拒绝整条结果。
- 正文指纹识别已登记原文的规范化完整副本；不声称识别任意拼接、截断、改写、同义表达或语义暗指。没有规则时不改变原工具结果的行为。

本次仅修复网络外发前检查和结构化工具结果旁路；HIST-02 普通检索的轮次来源关联由 HIST 负责人独立修复并验收。
