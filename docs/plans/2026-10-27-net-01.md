# NET-01 Controlled Search and Web Extraction Implementation Plan

**Goal:** Desktop tools can perform permission-gated real searches and extract read-only public pages with verifiable provenance.

**Architecture:** Keep ToolGateway as the only model entry point. Inject a bounded, DNS-pinned HTTP transport and configured search adapter in desktop composition. Persist only credential references in config; resolve secrets from the existing vault per request. External content is untrusted evidence, never instructions.

**Tech Stack:** Python 3.12, stdlib HTTP/TLS/HTML parser, Pydantic, existing Qt settings and pytest.

## Decisions (2026-10-27)
- Recommended: SerpAPI Google/Bing (explicitly third-party), plus Tavily. No scraping search result HTML or automatic provider fallback.
- Direct legacy Bing is retired (2025-08-11); Google Custom Search is closed to new customers and ends for existing customers on 2027-01-01. Do not build a new-user setup around these APIs.
- Defer model-native grounding: it requires provider-specific runtime and citation contracts.
- Search remains explicit per-call authorization; a domain grant cannot silently authorize arbitrary query disclosure. Page redirects to another origin return a new target for a separate permission-gated read.
- Disable search by default. Keep page reading available behind existing network permissions. Never send cookies, ambient proxies, auth headers or model credentials to pages.

## Task 1: Configuration and contracts
Files: domain/network.py, domain/configuration.py, application/services/settings_service.py.
1. Add validated provider, credential reference and result count configuration.
2. Add safe structured network errors, page response and evidence notes.
3. Preserve network configuration through all settings rebuilds; test defaults and round trips.

## Task 2: HTTP and extraction
Files: infrastructure/web_access.py, application/services/web_content.py, tests/unit/test_web_access.py.
1. Write failing tests for forbidden IPs, DNS rebinding, redirects, timeouts, size/MIME/status failures and HTML cleaning.
2. Implement HTTP(S)-only public-address validation, pinned connections with original TLS hostname, bounded reads and same-origin redirect checks.
3. Extract title/text, remove executable/navigation/form content, preserve actual final URL and retrieval time, mark truncation.

## Task 3: Search adapters and gateway
Files: infrastructure/web_search.py, application/services/tool_gateway.py, tests/unit/test_web_search.py, tests/unit/test_tool_gateway.py.
1. Test SerpAPI Google/Bing and Tavily response normalization with fake transports.
2. Implement fixed endpoints, per-call credentials, bounded normalized sources and redacted structured failures.
3. Inject providers and apply gateway output limits and external-evidence notes; verify permission/web-origin denial causes no network access.

## Task 4: Desktop settings and wiring
Files: ui/network_settings_page.py, ui/settings_panel.py, app.py, tests/ui/test_network_settings.py.
1. Add a lazy settings page using existing visual conventions: provider, masked new key, result limit, save and clear-key controls, truthful provider/status help.
2. Save secrets only to the vault; locked state cannot store keys. Never prefill plaintext keys.
3. Construct network backend before tool IPC starts; resolve saved settings dynamically without restart.

## Task 5: Model behavior and verification
Files: infrastructure/extensions/policy_enforcement.ts, docs/development/network-access.md.
1. Explain search snippets versus fetched article evidence in tool descriptions and results; require sources/retrieval time and honest failure handling.
2. Document provider setup, limits, privacy and intentionally unsupported features.
3. Run focused tests, lint/type checks and broader regressions. Live provider searches require user credentials; do not claim they passed without credentials.

No unrelated changes or commits; preserve the pre-existing in-progress privacy work.
