# 会话切换加载优化实现计划

**目标：** 并行准备历史显示与运行时恢复数据，缩短切换等待，同时保持失败时原会话和草稿。

**架构：** 先在存储后台读取历史载荷并确定目标分支，然后并行执行 Markdown/附件预处理与运行时快照准备。两项都成功后，在原有命令仲裁和运行时切换保护下恢复内核、更新界面。预读结果绑定协调器、目标、源定位和执行修订号；不匹配则重新读取。快照优先由现有存储进程计算，无进程时使用可取消并等待结束的后台线程。

**技术：** Python asyncio、现有 ConversationProcess 与 HistoryReader、PySide6/qasync。

1. 为协调器添加只读快照预准备接口和有效性校验，控制器转发接口；保留未预准备调用的行为。
2. 将桌面历史加载拆分成读取载荷与显示预处理，使用 TaskGroup 并行显示预处理和快照准备；失败/取消时等待后台工作释放资源。
3. 增加基于事件屏障的并行回归测试，验证预准备复用、过期重读、读取失败不切换、取消/退出等待与真实存储进程路径。
4. 运行历史加载、会话浏览/草稿、队列、协调器和存储进程相关测试及变更文件静态检查。使用合成延迟比较串行与并行阶段，报告测试条件下结果，不推算真实全流程倍数。

工作区已有大量未提交修改；本次仅增量修改相关路径，不提交或覆盖原有工作。

## 验证记录

- 核心历史加载、预准备与真实存储进程：41 项通过；另加退出期间等待快照线程的测试通过。
- 草稿、后台生成时浏览、队列、业务卸载、重生成、协调器、分支、RuntimeFacade 与恢复回归：140 项通过。1 项旧测试仍在不存在会话的显示预处理阶段设置屏障，拆分后该阶段不再进入，已调整为在载荷读取阶段设置同一屏障；最终相关文件 38 项复测全部通过。各轮去重后共有 182 项相关回归通过。
- 三个生产文件 mypy 严格检查通过，变更文件 Ruff 检查通过。
- 合成延迟实验：真实桌面切换接线、单轮两条消息，Markdown 和快照准备分别注入 200ms 延迟；串行/并行交替各 3 次。在运行其他回归测试的本机上，切换总耗时中位数为 533.6ms / 354.9ms，减少约 33.5%。这是固定延迟实验，不代表真实资料库全流程的提速比例。屏障回归另外验证两项工作在释放任何一项前都已开始，且由不同后台线程执行。

## 第二轮：减少读取量（2026-10-15）

用户反馈真实读取仍慢。用真实字段加密的 SQLite 合成会话分析，6 分支 × 每分支 200 轮，包含大块工具输出。优化前历史载荷读取中位数 233.53ms，快照准备 577.04ms。cProfile 显示当前分支定位会解密所有分支消息，快照准备会解密所有分支镜像。

实施：
1. 消息仓库新增按分支批量计数和最大时间的元数据查询，当前分支选择和分支列表复用，避免读取无关正文。
2. 运行时元数据与完整镜像区分类型。先读取拓扑元数据并沿目标叶子回溯，仅按需解密目标路径镜像；原有全量读取接口继续供审计等调用。压缩边界判定仅使用元数据，保持压缩/分叉语义。
3. 未发生压缩变换时复用已经计算好的快照指纹，避免重复处理同一内容。
4. 桌面记录载荷读取、显示准备、快照准备、恢复、控件渲染的分段耗时，日志不含会话正文或附件内容。
5. 用仓库双后端、分叉/压缩/污染隔离、真实子进程和界面加载回归验证。通过解密次数及禁止访问无关密文的断言防止回退到全量读取。复用同一合成负载测量前后耗时。

### 第二轮完成与验证

- 新增 schema 18 迁移：为消息活动聚合、运行时拓扑元数据提供覆盖索引，不修改消息/镜像正文。迁移测试覆盖 17→18 升级、查询计划不访问正文表页、第二个索引创建失败时第一个索引与版本号均回滚。
- 读取拓扑与按需读取密文固定在同一个 SQLite 读快照中。并发删除测试验证不会拼出半份上下文。
- 本轮相关测试分进程运行共 **592 项通过**，覆盖读取量、双后端、持久化、迁移/备份恢复、分支、压缩、污染隔离、子进程、界面加载/浏览、草稿及队列。一次混合长进程测试在 Qt 事件处理中出现 access violation，没有完成；拆分后所有相同测试文件与新增兼容性测试均通过。11 个生产文件 mypy 严格检查通过，变更文件 Ruff 通过。
- 新增可复测脚本 `scripts/benchmark_session_loading.py`，只创建临时合成加密数据库。两个相同数据库分别运行旧读取算法/旧索引与新读取算法/新索引，交替采样 5 次，预热不计入；断言历史载荷与完整恢复快照相等。计时包含数据库读取、解密和数据投影，不包括 Qt 控件创建、Pi RPC 恢复、子进程冷启动或实际 Provider 请求。本机同时运行其他回归测试，因此绝对耗时存在波动，不将阶段耗时相加当作并行切换总耗时。
