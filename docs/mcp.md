# MCP 外部工具

LimboWave 作为 **MCP 客户端**，把你配置的服务器工具接入桌面对话。它不是向外暴露聊天记录的 MCP Server。

## 开始使用

1. 打开「设置 → 模型与连接 → MCP 服务器」，新增一个服务器。
2. 本地服务器选择 **stdio**：填写可执行文件、JSON 参数数组和可选工作目录。应用不把它们拼成 shell 字符串，不会自动安装 Node/Python 或服务器。请先自行安装可信服务器。
3. 远程服务器选择 **Streamable HTTP**：填写完整 MCP 地址。远程必须 HTTPS；只有 localhost / 127.0.0.1 / ::1 允许 HTTP。地址不能包含账号、密码、查询参数或片段，也不自动跟随跳转。
4. 服务器默认停用；勾选启用并保存后，对话才可发现它。**保存及应用启动均不会连接或运行服务器。**
5. 点击「连接并发现工具…」并确认，后台完成握手和工具目录读取。成功仅代表这次发现成功，不表示长期在线，也不证明每个工具都能执行。

## 凭据

配置文件为资料库目录内的 `mcp.json`。普通配置仅保存主机环境变量引用。

- stdio 环境引用示例：  `{"API_KEY": "MY_MCP_API_KEY"}` 将主机变量 MY_MCP_API_KEY 的值传给服务器的 API_KEY。
- HTTP 请求头引用示例：  `{"Authorization": "MY_MCP_AUTH"}`；主机变量的值应是完整请求头值，如 Bearer 加令牌。
- 在应用启动前设置环境变量，修改后重启应用。不在参数、显示名称或 URL 中粘贴秘密；参数和普通配置本身不加密。
- 不自动继承任意主机秘密，仅传 SDK 的最小基础环境与明确引用的值。服务器 stderr 被丢弃，传输异常不回显参数、地址或凭据。

## 对话调用

模型通过两个应用工具接入，无需重启 Pi：

- **list_mcp_tools**：无参数列出已启用服务器 ID；提供 server_id 时发现工具、描述与 inputSchema，可用 offset / limit 分页。
- **call_mcp_tool**：传入 server_id、tool 和符合 inputSchema 的 arguments。实际调用前重新发现并校验工具，工具名不会覆盖内置工具。

本地持久化 **完全访问** 自动允许 MCP，遵循全局权限规则；自定义模式逐次确认，不因为服务器宣称只读就免确认。纯聊天、只读与 Web 来源不能调用 MCP。非完全访问的工具参数和结果还要通过话题隐私规则；完全访问遵循全局调用级隐私豁免。

## 边界与注意事项

- 服务器是你信任并运行的外部软件，**不是沙盒**；一旦启动，它可能按自身权限读取文件、联网或执行其他操作。发现工具也会启动 stdio 程序。
- 工具说明、输出及资源链接都只是外部资料，不是指令；应用不会自动打开资源链接或代替服务器执行 sampling / elicitation 请求。
- 每次发现或调用使用独立、短生命周期会话，结束后关闭连接/进程；不承诺跨调用内存状态。仅用 tools 能力，不支持 OAuth、旧版 HTTP+SSE、resources、prompts、roots 或任务持久化。
- 总操作超时可设 1–45 秒，默认 20 秒。目录最多 256 工具、20 页、512 KiB，调用参数最多 64 KiB。网关结果有 64 KiB 上限；超大结果明确失败，不把截断内容当完整成功。
- 工具错误保留失败语义，超时/断连不自动重试。**超时、取消或输出超限时，服务端操作仍可能已发生**；先核对状态，尤其是写入、发布和支付类操作。
- 更新或删除配置影响后续调用；修改文件不会撤回已发往外部服务的请求。使用者应自行核实服务商的数据保存和访问策略。

实现与测试覆盖真实本地 stdio/HTTP 往返、分页、模式校验、错误、超时、来源边界、权限、隐私和原生设置交互。
