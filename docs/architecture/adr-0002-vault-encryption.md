# ADR-0002：资料库加密采用应用层信封加密，不使用 SQLCipher

- **状态**：已接受
- **日期**：2026-09-22
- **依据**：设计计划 §十二（本地存储与加密）、§建议技术栈
- **影响**：设计计划 §12.2 加密策略、§12.3 解锁与恢复、§14.1 历史搜索

---

## 一、背景

设计计划的建议技术栈（第 18 行）写的是「**SQLCipher 或应用层信封加密**」——
两条路都在计划许可范围内。本 ADR 记录为什么选后者。

## 二、实测证据

在目标环境（Windows 11 `10.0.26200` / CPython 3.12.13 / uv）实测：

| 候选 | 结论 | 证据 |
| --- | --- | --- |
| `sqlcipher3-binary` | **不可用** | 无 `win_amd64` + `cp312` wheel。已发布 wheel 只到 `cp311`，且 `0.6.0` 仅 `manylinux_2_17_x86_64` / `manylinux2014_x86_64` |
| `pysqlcipher3` | **不可用** | 仅源码分发（sdist）。编译需 C 工具链 + libsqlcipher + OpenSSL 开发头文件 |
| 本机 C 工具链 | **不存在** | `cl`（MSVC）与 `gcc` 均不在 PATH |
| 标准库 `sqlite3` | **可用** | SQLite `3.50.4`，**FTS5 可用** |

## 三、决策

**采用应用层信封加密，数据库使用标准库 `sqlite3`。**

理由：

1. **零原生依赖。** 标准库 `sqlite3` 随 Python 分发，不需编译，打包（PyInstaller/Nuitka）时也不引入 OpenSSL。
2. **设计计划已许可。** 第 18 行明确列出该选项。
3. **信封加密的全部要点都能满足。** §12.2 要求的「随机主密钥 / Argon2id 派生 / 改密码只重新封装」与是否使用 SQLCipher 无关，全部可实现。
4. **跨平台一致。** 首版虽只做 Windows，但纯 Python 方案不会在换平台时失效。

代价与已知限制（**如实记录，不掩盖**）：

1. **不是整库加密。** `sqlite3` 的页级/文件级无加密。因此加密粒度是**字段级**，
   而非设计计划字面的「数据库加密」。非敏感元数据（ID、时间戳、角色、状态）保持明文。
2. **FTS5 无法索引密文。** §14.1 要求对会话标题、用户消息、助手回答做 FTS5 搜索，
   而这些字段正是加密对象——密文上做全文匹配没有意义。
   §18.3 已为此预留原则（「搜索索引只存在于加密数据库；解锁后查询」），
   但由于密文不可索引，**Phase 9 的搜索需改为解锁后在内存中对已解密内容检索**。
   对个人自用规模（§10.2 的 2,000 条消息）完全可行。
3. **主密钥在解锁期间存在于进程内存。** Python 无法可靠地擦除内存，`lock()` 只能丢弃引用。
   这是所有纯用户态加密方案的共同限制，DLL 层加密（如 SQLCipher）也不能免除。
4. **元数据泄露面。** 会话数量、消息数量、时间戳、消息长度（密文长度）对拿到数据库文件的
   攻击者可见。SQLCipher 可以隐藏这些。**这是本决策最实质的安全代价。**

## 四、加密边界

```
主密码
  → Argon2id（salt 存于 vault.json，参数一并记录）
  → KEK（32 字节）
  → 包裹资料库主密钥（ChaCha20-Poly1305）
  → 资料库主密钥（32 字节，随机）
  → 加密敏感字段（ChaCha20-Poly1305，逐值随机 nonce）
```

- 主密钥**只以密文形式**落盘（`wrapped_master_key`）。
- 改主密码**只重新封装主密钥**，不重写任何数据（§12.2 要求）。
- KDF 参数写入 `vault.json`，因此将来调整参数不会破坏既有资料库。

## 五、对既有实现的处置

`infrastructure/crypto/secret_store.py` 原先把主密钥**明文**放在 `vault/master.key`。
那是我在 Phase 1A 记录的阶段性限制，本 ADR 落地时被**信封加密取代**：
主密钥改由主密码派生的 KEK 包裹，磁盘上不再有可用的明文密钥。

## 六、后续

- **Phase 1.3 Windows Hello 恢复**：在 `vault.json` 增加第二个密钥包装
  （DPAPI / 系统密钥保护），与主密码包装并列。本 ADR 的格式已预留 `wraps` 列表结构。
- **Phase 9 搜索**：按 §三.2 的结论实现内存检索，不再依赖 FTS5 索引密文。
